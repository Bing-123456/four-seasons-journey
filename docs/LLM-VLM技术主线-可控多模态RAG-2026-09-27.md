# LLM / VLM 技术主线方案：可控多模态 RAG

- **起因**：2026-09-27，你提出「传统的机器学习我们也可以搞，但是我们主要也要想想搞一些 LLM 和 VLM 之类的」
- **先说结论**：
  1. **技术含量不在「训模型」，在「架构设计」。** 我们数据不够训 LLM，但**不需要训**——把 LLM/VLM 的能力用出层次，本身就是技术含量。
  2. **主线定为「可控多模态 RAG」**：检索质量（BM25 + 稠密向量 + 重排）× 可控性（16 条闸门 + 引用核验 + 拒答）× 多模态（以图搜文）。
  3. **每一层都是一个消融组**——技术点不再是散的，而是**一条可以逐层验证的管线**。这是解决「技术点太散」的真正办法。
  4. **传统 ML 降为备选**（VLM 微调、CNN 对照），不当主线，但可以在消融实验里当对照组用。

---

## 一、现状：我们已经在用 LLM/VLM，但都是「调 API」

盘一下现有 6 个任务接口（`server/tasks.js`）：

| 任务 | 用的是什么 | 技术含量 |
|---|---|---|
| `ask` | LLM 从证据里挑 ID | 架构设计有价值，但**调用本身是 1 次 API** |
| `identifyFruit` | **VLM**（qwen-vl-plus）从 14 类里选 | 同上 |
| `fruitStory` | LLM 写故事 | 纯生成 |
| `translate` | LLM 翻译 | 纯生成 |
| `sellerInsight` | LLM 写解读 | 纯生成 |
| `profile` | LLM 抽结构化字段 | 信息抽取 |

**问题**：这六个都是「**一次 API 调用**」。评审问「你们的技术创新在哪」，答「我们调了 LLM」——这是所有人都能做的事。

**而且 `identifyFruit` 有个隐藏的信息损失**：

```js
// 现在的做法：VLM 输出一个水果名，然后按名字查详情
user: '看照片判断是什么果树或果实，只能从候选清单中选择：' + JSON.stringify({ candidates: fruitNames })
→ 输出 {"fruit":"苹果"} → findFruitByName('苹果') → 跳详情页
```

**一张照片的全部信息被压缩成了一个字符串。** 用户拍的是「一棵挂着青果的树，树下有农人在疏果」，系统只知道「这是苹果」。**这就是可以升级的地方。**

## 二、技术含量从哪来：从「调用」升级到「架构」

**核心认知转换**：

| ❌ 不是这样 | ✅ 而是这样 |
|---|---|
| 「我们用了 LLM 做问答」 | 「我们设计了**约束式生成架构**，让 LLM 只能从核验证据里选，说不出就拒答」 |
| 「我们用了 VLM 识果」 | 「我们做了**跨模态检索**，让照片直接检索文化内容，而不是压缩成一个标签」 |
| 「我们调了向量模型」 | 「我们做了**混合检索 + 两阶段排序**，并用消融实验量化了每一层的贡献」 |

**同样的 API，不同的架构，技术含量差一个量级。**

而且——**这套架构的每一层都可以被单独关掉**，这就是消融实验，就是可量化的证据。

## 三、⭐ 核心技术栈：可控多模态 RAG（9 层）

| # | 层 | 技术 | 用什么 | 现状 |
|---|---|---|---|---|
| **L0** | **裸 LLM 对照组** | 无检索、无约束，直接问 | DeepSeek | ❌ **要加**（最重要的对照组） |
| **L1** | 稀疏检索 | BM25 | 现有 `rankFacts()` | ✅ 有 |
| **L2** | **范围与意图闸门** | 16 条拒答规则 | 现有 `resolve()` | ✅ 有 |
| **L3** | **稠密检索** | 多模态向量 | **`qwen3-vl-embedding`** | ❌ 要加 |
| **L4** | 混合融合 | RRF（倒数排名融合） | 自己实现（约 20 行） | ❌ 要加 |
| **L5** | **跨模态重排** | 多模态重排模型 | **`qwen3-vl-rerank`** | ❌ 要加 |
| **L6** | 证据选择 | 模型只挑 ID，不写事实 | 现有 `tasks.js` | ✅ 有 |
| **L7** | **引用核验** | LLM 做 NLI，判断引用是否被支持 | DeepSeek | ❌ 要加 |
| **L8** | 拒答 + 诚实降级 | `unanswerable` + `local-*` | 现有 | ✅ 有 |

**看这个表的结构**：
- **L1/L2/L6/L8 已经存在**（这是我们的存量资产，比想象的好）
- **L0/L3/L4/L5/L7 是要补的**（5 层，每层都不需要训练）
- **9 层，每层可单独开关** → 天然的消融实验矩阵

**关键点：这不是「重新叙述」，是真的要写代码加 5 层。** 加完之后，技术点从「散在代码里的规则」变成「一条有 9 个环节、每环节可测的管线」。

## 四、三个真正有技术含量的 LLM/VLM 技术点

### 技术点 1 ⭐⭐⭐：跨模态检索（以图搜文）

**现在的做法**：照片 → VLM → 水果名 → 按名查详情。**信息损失严重。**

**升级后**：

```
用户照片
   ↓ qwen3-vl-embedding 编码（图片 → 向量）
   ↓ 在 415 条文化内容向量库中检索（图片向量 vs 文本向量，同一语义空间）
   ↓ qwen3-vl-rerank 重排（query=图片，documents=候选文本）
   ↓ 返回相关文化内容 + 出处
```

**为什么这是质变**：

| 场景 | 现在（水果名匹配） | 升级后（跨模态检索） |
|---|---|---|
| 拍一张正在腌制的梅子 | 只识别出「青梅」→ 跳青梅详情 | 检索到「**芒种煮梅**」的节气食俗段落 |
| 拍一张挂在树上的柿子 | 只识别出「柿子」→ 跳柿子详情 | 检索到「**霜降摘柿**」的农事记录 |
| 拍一张果脯制作台 | 识别失败（不是水果） | 检索到「**果脯传统工艺**」的内容 |

**关键在于**：水果名只能匹配「这是什么水果」，跨模态检索能匹配「**这个场景在讲什么文化**」。**后者才是「智能文化」要的东西。**

**指标**：跨模态 hit@k（图片 query → 正确文化内容）

---

### 技术点 2 ⭐⭐⭐：混合检索 + 两阶段排序（标准 RAG 栈）

**现在**：纯 BM25 词频匹配。问题很明显——**同义改写就失效**。比如「做瓜豆酱用啥东西」能匹配，但「瓜豆酱的配料有哪些」可能就弱了。

**升级为四路**：

| 路 | 方法 | 强项 |
|---|---|---|
| 稀疏 | BM25（现有） | 精确词匹配、专有名词 |
| 稠密 | `qwen3-vl-embedding` | 语义相似、同义改写 |
| 融合 | **RRF**（倒数排名融合） | 无需调权重，两路结果自然合并 |
| 重排 | `qwen3-vl-rerank` | 二次精排，把最相关的顶上来 |

**这是学术界和工业界最标准的 RAG 检索栈**，评审一眼能认出，而且**每一路的增量都可以量化**：

```
BM25 单独        → hit@1 0.714（已测）
BM25 + 闸门      → hit@1 0.857（已测）
+ 稠密检索       → hit@1 ?
+ RRF 融合       → hit@1 ?
+ qwen3-vl-rerank → hit@1 ?
```

**五个数字排成一张表，就是「技术含量」。**

---

### 技术点 3 ⭐⭐：LLM 引用核验器（防幻觉）

**问题**：文化类内容最怕的不是答不出来，是**编造出处**。

**做法**：用 LLM 做 NLI（自然语言推理）——给定「生成的答案」和「引用的证据」，判断**证据是否真的支持这个答案**。

```
输入：{ claim: "瓜豆酱的原料是黄豆和西瓜", evidence: "…瓜豆酱以黄豆、西瓜为原料…" }
输出：{ supported: true, confidence: 0.95 }
```

**为什么这个方向好**：

| 优势 | 说明 |
|---|---|
| **不需要训练** | 用现成 LLM 做推理即可，**完全规避了「数据不够」的短板** |
| **负样本可自动构造** | 把事实里的数字/地名/节气名换掉 → 变成「不被支持」→ 零人工成本 |
| **有天然的消融对照** | 无校验 / 字面 5-gram 校验 / LLM 语义校验，**三组一张表** |
| **直接对应我们的主线** | 「可控生成」的核心就是「说的每句话都有出处」 |

**指标**：准确率 / F1 / **假阳性率**（把「不支持」误判成「支持」是最危险的错误）。

## 五、消融实验设计（把技术点变成证据）

**这是整个方案的关键动作**。现有评测框架（`scripts/evaluate-retrieval.js`）**已经支持多组对照**，只要往里加组即可：

| 组 | 配置 | 预期 | 现状 |
|---|---|---|---|
| **A** | **裸 LLM**（无检索无约束） | 8 条不可答问题**全部硬答**，拒答召回 0 | ❌ 要加 |
| B | BM25 | hit@1 0.714 / **拒答召回 0** | ✅ 已测 |
| C | BM25 + 16 条闸门 | hit@1 0.857 / **拒答召回 1.000** / 误拒率 0.071 | ✅ 已测 |
| D | C + 稠密检索（向量） | hit@1 ↑ | ❌ 要加 |
| E | D + RRF 融合 | hit@1 ↑ | ❌ 要加 |
| F | E + `qwen3-vl-rerank` 重排 | hit@1 ↑↑ | ❌ 要加 |
| G | F + LLM 引用核验 | 幻觉率 ↓↓ | ❌ 要加 |
| H | G + 跨模态检索（图片 query） | 跨模态 hit@k | ❌ 要加 |

**A 组是灵魂**。因为：

> 「**裸 LLM 在 8 条知识库无答案的问题上，100% 编造了回答（拒答召回 0）；我们的系统 100% 拒答（拒答召回 1.000）。**」

**这一句话就是整个作品的答辩开场白。** 而且它需要 A 组实测数据支撑。

**B→C 的跃迁已经测出来了**：拒答召回 **0 → 1.000**，代价是误拒率 0 → 0.071。**这个权衡本身就是论文级的讨论点。**

## 六、接口与成本（已核实）

### 6.1 多模态向量：`qwen3-vl-embedding`

| 项 | 值 |
|---|---|
| Endpoint | `POST https://dashscope.aliyuncs.com/api/v1/services/embeddings/multimodal-embedding/multimodal-embedding` |
| 维度 | 默认 2560，可选 2048/1536/1024/768/512/256 |
| 输入 | **文本、图片、视频，同一语义空间** |
| 语种 | 33 种主流语言 |
| 文本长度 | 32,000 token |
| 图片限制 | 单张 ≤ 10 MB，JPEG/PNG/WEBP/BMP 等 |
| **价格** | 图片 0.0018 元/千 token；文本 0.0007 元/千 token |
| **免费额度** | **100 万 token**（90 天） |

> 💡 **架构决策**：**统一用多模态向量模型处理文本和图片**，不要分别用文本 embedding 和多模态 embedding。
> 理由：同一个模型 → **天然在同一向量空间** → 跨模态检索不需要任何对齐工作。这是最简洁的设计。
> 415 条内容的 embedding 成本几乎为零（远在免费额度内）。

### 6.2 多模态重排：`qwen3-vl-rerank`

| 项 | 值 |
|---|---|
| Endpoint | `POST https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/rerank/text-rerank/text-rerank` |
| **query 支持图片** | `{"query": {"image": "URL或Base64"}}` ← **跨模态重排的关键** |
| documents | 文本 / 图片 / 视频混合 |
| 最大文档数 | 文本 100 / 图片 40 / 视频 4 |
| 单条最大 token | 8,000 |
| 返回 | `relevance_score`（0.0–1.0）+ `index` |
| `instruct` 参数 | 可指定排序策略，**英文撰写可提升 1–5%** |

> ⚠️ **一个要实测的不确定点**：官方文档给的 rerank endpoint 是 `{WorkspaceId}.cn-beijing.maas.aliyuncs.com` 形式，需要业务空间 ID。
> 而我们项目现在用的是 `dashscope.aliyuncs.com/compatible-mode/v1`（VLM 走这条）。
> **动手前先确认 rerank 在老域名下能不能调通**——如果不能，需要在百炼控制台拿 WorkspaceId，并在 `server/config.js` 加一个配置项。
> 另外注意：**`gte-rerank-v2` 将于 2026-05-30 下线**，不要用它，直接用 `qwen3-vl-rerank`。

### 6.3 成本估算

| 项 | 用量 | 成本 |
|---|---|---|
| 415 条内容 embedding（一次性） | 约 20 万 token | **免费额度内** |
| 评测集 32 条 × 多组消融 | 约 10 万 token | **免费额度内** |
| 单次用户查询（检索+重排+核验） | 约 5k token | 约 0.004 元 |

**结论：整个方案在 100 万免费额度内基本能跑完，成本不是障碍。**

## 七、传统 ML 的位置：降为对照组，不当主线

你说「传统的机器学习也可以搞」——**可以，但让它服务主线**：

| 传统 ML 用法 | 位置 | 价值 |
|---|---|---|
| **CNN 做 14 类水果分类** | 作为**对照实验**和 VLM/跨模态检索比 | 「传统 CNN vs VLM zero-shot vs 跨模态检索」三组对照 |
| **TF-IDF / SVM 做意图分类** | 作为**弱基线** | 证明深度检索有必要 |
| **LightGBM 做重排** | **可替代 `qwen3-vl-rerank`** | 但要自己造训练数据 → **标签自造问题，不推荐** |

**推荐**：**把传统 ML 放在「对照组」的位置**。这样既满足了「传统 ML 也可以搞」，又不会让它拖散主线——**它成了主线论证的一部分，而不是另一条线。**

## 八、不做什么（附理由）

| 不做 | 理由 |
|---|---|
| **LLM 微调（SFT/LoRA）** | 数据差 15–300 倍，且自生成自评测会失真 |
| **自训重排器（LightGBM Ranker）** | 标签来自我们自己写的规则 → 循环论证，答辩撑不住 |
| **VLM 微调做水果分类** | 可以做，但**优先级低于跨模态检索**——检索解决的是「找什么」，分类只解决「是什么」 |
| **滞销预测 / 销量预测** | 无真实数据，只登记启动门槛 |
| **用 `gte-rerank-v2`** | 2026-05-30 下线 |
| **纯向量检索替代 BM25** | 稀疏+稠密混合才是标准做法，专有名词（瓜豆酱、青谷堆）靠 BM25 更准 |

## 十、答辩怎么讲

**不要说**：「我们用了 LLM 和 VLM 做文化问答」。
**要说**：

> 「我们的作品是面向中国本土果品与农耕文化的知识问答系统。这类系统最怕两件事：**答不出来硬答**，和**编造出处**。
>
> 我们设计了一条 **9 层可控生成管线**：从范围闸门、意图识别，到混合检索、两阶段重排，再到证据锚定、引用核验和拒答降级。
>
> **关键是我们量化了每一层的贡献**。比如——**裸 LLM 在我们评测集的 8 条知识库无答案问题上，100% 编造了回答；加上 16 条闸门后，拒答召回从 0 提升到 1.000，代价是误拒率 0.071。** 检索侧，我们从纯 BM25 的 hit@1 0.714，逐层加到混合检索和重排，提升到 〔X〕。
>
> 多模态方面，我们没有停在「拍照片识别水果」——**我们把照片直接编码进文化内容的语义空间做跨模态检索**。用户拍一张正在腌制的梅子，系统返回的是「芒种煮梅」的节气食俗，而不只是「这是青梅」。
>
> 所有模型调用都经过引用核验，**核验不通过的引用不会出现在答案里**。模型不可用时，系统会明确告诉用户服务暂不可用，**我们不假装 AI 在工作**。」

**为什么这套说法强**：
1. **有 9 层架构**——不是「调了 API」
2. **有 8 组消融数据**——每层贡献可量化
3. **有对照**——裸 LLM vs 我们的系统，对比极其鲜明
4. **多模态有真场景**——不是炫技
5. **有诚实性**——拒答 + 降级 + 核验，是「智能文化」最该讲的东西

## 十一、一句话回答你的问题

**传统 ML 可以搞，但让它当对照组；主线放在 LLM/VLM 的「架构」上。**

- **不要训 LLM**（数据差 15–300 倍），**也不要训重排器**（标签自造）
- **要做的是把 LLM/VLM 用出层次**：**9 层可控多模态 RAG 管线**
- **三个技术点**：
  1. **跨模态检索**（照片直接检索文化内容，而不是压缩成水果名）
  2. **混合检索 + 两阶段排序**（BM25 + `qwen3-vl-embedding` + RRF + `qwen3-vl-rerank`）
  3. **LLM 引用核验器**（不需要训练，自动构造负样本，有天然消融对照）
- **最关键的一个动作**：**补上「裸 LLM」对照组**——「裸 LLM 拒答召回 0，我们 1.000」这一句话，比十个功能都有说服力
- **成本不是问题**：100 万免费额度足够跑完全部实验
- **技术点从「散」变「一条线」的方法**：**9 层每层可单独开关，跑 8 组消融**——技术点就不再是散的，而是**可逐层验证的证据**

**技术没变复杂，是变得有结构了。**

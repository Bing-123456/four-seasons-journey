## 客户反馈「点击后没有内容」「爱心不变红」的根因

`pages/calendar/calendar.wxml` 把判断写在视图表达式里：

```
wx:if="{{expandedCats.indexOf(item.cat) >= 0}}"
class="fruit-fav {{knowledgeFavorites.indexOf(...) >= 0 ? 'is-fav' : ''}}"
```

WXML 表达式引擎**不执行 `Array.prototype.indexOf`**，该调用返回假值。实测：页面上 `expandedCats` 已经是 `["folk","history"]`、`item.cat` 也能正确渲染出 `id="fruit-cat-history"`，但 `.fruit-cat-body`、`.fruit-cat-detail` 在 DOM 中根本不存在（`selectAll('.fruit-cat-detail')` 计数为 0）。因此：

- 点开水果后正文永远不显示 → 「点击后没有内容」；
- 爱心类名恒为空 → 点击后不会变红色实心。

修复方式：新增 `decorateFruit()`，在 JS 里把每个板块的 `open`（是否展开）、`fav`（是否已收藏）、`label`、`favId` 算成布尔值/字符串再交给视图，wxml 只读 `item.open` / `item.fav`。修复后实测 `.fruit-cat-detail` 正常渲染（计数 2），爱心点亮/复原均生效。

同类隐患：`pages/favorites/favorites.wxml` 的 `{{item.name.slice(0, 1)}}` 同样在视图里调方法，已改为使用 JS 侧算好的 `item.initial`。

为防止复发，`scripts/check-project.js` 增加规则：WXML 表达式中出现 `indexOf / includes / slice / filter / map` 等数组、字符串方法调用即报错。

## 顺带修掉的两处控制台告警

重启开发者工具后直接读窗口截图与控制台，发现两条真实告警（都不影响本次需求，但同页出现）：

1. `[pages/calendar/calendar] Do not set same key "[object Object]" in wx:key` —— `monthItems` 是对象数组却写了 `wx:key="*this"`，所有键都退化成同一个字符串，会干扰列表复用。改为 `wx:key="label"`。（全项目排查过：其余 `wx:key="*this"` 都作用在字符串数组上，写法正确。）
2. `[Component] property "config" of companion-view received type-uncompatible value: expected <Object> but got non-Object value` —— `companionMini` 首次渲染还是 `null`。改为 `wx:if="{{companionMini}}"` 后再挂载。

同时补上 `pages/calendar/calendar.json` 的 `companion-view` 组件注册（搜索入口搬到本页后新增的用法，之前漏注册）。

修复后重启应用实测：导航栏与欢迎页显示「果物四时记」，果灵形象正常渲染，控制台无报错。截图见 `test-results/revamp-20260925/01-app-running-rename.png`。

## 边界

- 农事活动为**演示性活动预告**，预约开放时间为大致起始时间，出行前须向主办方核实；应用不提供场地预约。
- 外圈水果的民俗、农谚属民间流传，栽培史与用途取自公开农书、地方志与常见史料；未做实地走访或第三方史料核对，属展示层内容，不进入行程算法与果农批次。
- 手绘风为 WXSS 近似实现（不规则圆角 + 描边），未引入手绘位图素材。
- 本轮未上传微信体验版、未做真机权限验收。

# 仅同步小程序前端到 VPS

脚本：`scripts/sync-frontend-vps.sh`。目标固定为 SSH 别名 `maker-camp`（60.204.231.189），更新 `/opt/guayouji/current/miniprogram`。适用于前端界面、插图和小程序文件完成本机验收后的同步。

脚本不读取或修改 `.env`、`server`、nginx、systemd 配置，不执行服务停止、重启或 reload。`current` 发布链接保持不变。VPS 文件同步不等于发布微信小程序，微信开发者工具上传仍是独立流程。

## 本机检查与同步

先完成相关行为测试、`npm run check` 和微信开发者工具界面验收。同步期间不要继续修改本机前端，也不要并行执行完整发布脚本。

```sh
# 只在本机打包并校验，不连接 VPS；临时包随后清理。
bash scripts/sync-frontend-vps.sh --check

# 执行前端同步。
bash scripts/sync-frontend-vps.sh
```

需要本机 Python 3、SSH，以及现有 root SSH 账户。远端需要 Python 3 和支持 `renameat2(RENAME_EXCHANGE)` 的 Linux/libc；不支持时会在切换前停止。SSH 使用现有密钥与主机信任配置，不关闭主机密钥验证。

同步步骤：

1. 仅打包 `miniprogram`，生成包含每个文件路径、长度、SHA-256 和目录清单的 manifest。忽略 `.DS_Store` 与 macOS `._` 附带文件；符号链接、私密配置/密钥文件名与非常规文件会中止打包。
2. 上传到独立、仅 root 可读的 `/opt/guayouji/frontend-sync/<UTC时间-PID>/`，校验整个压缩包的 SHA-256。远端文件锁阻止并行前端同步/回滚。
3. 为原有 `miniprogram` 创建完整 `miniprogram.before.tar.gz` 备份，逐文件核对备份内容，并保存旧目录清单和压缩包 SHA-256。
4. 解压至当前发布目录内的 `.frontend-sync-<同步编号>/miniprogram`。只接受 `miniprogram` 下的普通文件和目录，拒绝越界路径、重复条目和链接。逐文件校验文件内容、长度和完整清单，防止遗漏或多出文件。新目录保留原前端目录的属主，目录权限为 755，文件权限为 644。
5. 原子交换暂存目录与当前 `miniprogram`，没有两次移动造成的空目录窗口。再次校验新旧目录；交换后失败或收到可处理的中断信号，会自动交换恢复。

## 保留内容与回滚

成功后会打印同步编号、旧目录、完整备份位置和准确的回滚命令。脚本不自动清理远端备份。

| 内容 | 位置 |
| --- | --- |
| 当前前端 | `/opt/guayouji/current/miniprogram` |
| 完整旧目录 | 当前实际 release 下的 `.frontend-sync-<同步编号>/miniprogram` |
| 完整旧目录压缩备份 | `/opt/guayouji/frontend-sync/<同步编号>/miniprogram.before.tar.gz` |
| 文件清单、压缩包、切换记录 | 同一 `frontend-sync/<同步编号>/` 目录 |

使用成功输出中的编号回滚：

```sh
bash scripts/sync-frontend-vps.sh --rollback 20260926T030000Z-12345
```

回滚会先确认当前 release 未改变、当前前端仍逐文件匹配该次上传、保留旧目录仍匹配原清单，再原子交换恢复。后续同步或手动改过文件时会拒绝覆盖；应先处理较新的同步记录。回滚后的被替换版本仍保留在该暂存目录，完整压缩备份始终保留。

`receipt.json` 记录 `prepared`、`active` 或回滚状态。对于进程被强制终止等无法自动处理的情况，保留目录和完整备份可用于恢复；若交换已完成且清单仍匹配，`--rollback` 也接受 `prepared` 记录。不要直接删除暂存目录后再尝试回滚。

服务端会引用部分 `miniprogram/lib` 和 `miniprogram/data` 模块。本脚本不会重启 Node，已加载的模块不会因此重新加载；涉及服务端运行逻辑的改动，应使用经过验收的完整发布流程。

# 问果灵「答非所问」修复报告 · 2026-09-28

> 评审 9.28 反馈（最重要问题）：问「凤梨和菠萝是什么关系」答案偏题；问「凤梨酥馅为啥要掺冬瓜」通篇没回答问点。
> 修复原则（用户红线）：**不许过拟合**——禁止针对具体问题写关键词补丁；全部机制通用，金标集分「调参/留出」双集验证。

## 根因
1. 服务端旧提示词只约束「只依据资料」，没有约束「先回应问点」——模型拿到整份多维度材料后倾向于概述资料而非回答问题。
2. 资料回答不了问点时（如材料里没有「为什么掺冬瓜」），模型会绕开问点改讲材料里碰巧有的内容。
3. 客户端上下文按固定维度顺序拼接，「与问点相关的分块」可能被 1800 字截断吃掉，进一步带偏回答。

## 通用修复（无任何具体问题特判）
| 层 | 文件 | 机制 |
|-|-|-|
| 服务端提示词 | server/chat.js SYSTEM | 回答铁律：先判断能否答 → 能答则第一句直接回应问点（比较题先给结论、为什么题先给原因）→ 不能答则第一句「素材库里没有」并点出问点，最多两句给最相关已核实内容并注明非直接答案 |
| 服务端答点守卫 | server/chat.js focusTermsOf/answerAddresses/isHonestRefusal | 从问题抽「双实义字」问点词；回答既不覆盖任何问点词、又不是诚实拒答 → 带纠正指令重答一次；仍不合格 → 替换为诚实拒答模板（回引原问题，绝不编造）。重答失败降级为拒答而非报错。temperature 0.5→0.3 |
| 客户端相关性排序 | miniprogram/pages/search/search.js buildContexts(fruits, question) | 各维度分块按与问点的词重合数排序再拼接：相关材料在前，1800 字截断只吃无关尾巴 |
| 客户端路由别名 | matchFruits | 「*子」类果名加单字根别名（桃子→桃、李子→李，沿用既有 秋梨→梨/青梅→梅/菠萝→凤梨 模式）＋排斥词（樱桃/猕猴桃/杨桃/核桃 不误伤桃子，行李不误伤李子），让「桃木辟邪」这类问法仍能路由到对应水果 |

## 验证（真实 DeepSeek，本地起服同源路径）
- 金标 17 题：调参集 8（事实/比较/关系/为什么·无答案/怎么做/闲聊/境外）＋留出集 9（含西瓜名字、含桃、西瓜酱、盐水泡菠萝、年节砂糖橘、樱桃车厘子、桃木辟邪、法国酒庄、苹果手机）。
- 判据三层：路由（该本地答复的不打模型）、must_include（答点词/拒答话术）、forbidden（编造红词）。
- 结果：**调参 8/8、留出 9/9、合计 17/17 全过**（明细 test-results/chat-eval-after.json / chat-eval-after2.json；修复前同集在本机初跑时 T4/T5/H6/H7 均为答非所问或路由失败）。

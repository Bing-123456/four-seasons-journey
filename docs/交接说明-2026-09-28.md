### 怎么确认插件真的可用了（不是「网页打开了」就算）

用 `miniprogram-automator` 连开发者工具（`ws://127.0.0.1:9420`），在模拟器上下文里直接探测：

```
requirePlugin('WechatSI')            → 拿到对象，getRecordRecognitionManager / textToSpeech 都是 function
recordRecoManager 的回调属性        → 都是可写数据属性，出厂值 function(e){}

开发者工具控制台                     → 零 error / exception
```

复跑命令：`node scripts/probe-plugin-wiring.js`（需开发者工具已打开本项目）。

### ⚠️ 探出来的一个真坑：插件回调必须用「赋值式」

`manager.onStart/onStop/onError/onRecognize` 是**可写数据属性、出厂值是空函数**，
而 `manager.start` 内部是 `setCallback("onStop", this.onStop)` —— **读属性当前值**再注册。所以：

```js
manager.onStop = fn      // ✅ 对（官方示例代码的写法）
manager.onStop(fn)       // ❌ 错：静默空转，回调永远不来，界面表现为「点了没反应」
```

官方文档的**方法表**写成「onStop callback」，很容易被误读成注册器；**以官方示例代码为准**。
对照：`wx.getRecorderManager().onStop(cb)` 才是真·注册器，而且**会叠加监听器**，
所以那边用 `WeakMap` 保证只绑一次。**两条链路的注册方式不一样，别互相套用。**

这一条差点被漏掉：本机模拟器不支持录音，探测时两种写法都是「零回调」，
只有把 `start` 的源码 dump 出来才看清真相。

### 错误分级（服务端兜底链路，`server/asr.js`）

| code | HTTP | 含义 |
|---|---|---|
| `asr_invalid` | 400 | 格式/语言/音频字节不合法 |
| `body_too_large` | 413 | 解码后音频 > 1.5 MB |
| `asr_empty` | 422 | **provider 正常应答，但一个字都没听出来** |
| `asr_disabled` | 503 | 未配置 key，提示改用键盘 |
| `asr_unavailable` | 502 | provider 调用失败 |

> `asr_empty` 与 `asr_unavailable` 必须分开——否则「模型没听清」会被当成「服务故障」计入监控。
> 这条与「评测集引用错位」是同一类错误：**别让一种失败伪装成另一种失败。**

插件侧错误码：`onError` 回调字段是 **`retcode`**（不是 `code`），值为负数 `-30001 ~ -40001`，共 14 个，全部有中文文案。

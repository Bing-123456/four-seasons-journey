## 四、2026-09-28 变更：语音输入改为**双引擎**（插件优先 + 服务端兜底）

### 现在的形态

```
① 微信同声传译插件（首选）    requirePlugin('WechatSI') → recordRecoManager
                              流式，边说边出字；免费（250 条/分、3 万条/天）；不消耗我们的额度
② 原生录音 + 服务端识别（兜底）wx.getRecorderManager() → base64 → POST /api/asr
                              → server/asr.js → DashScope qwen3-asr-flash
```

`voice.engine` 会告诉你这次实际走的哪条（`'plugin'` / `'server'`），**降级是可观测的**。

### 为什么是双引擎，而不是只用其中一个

- **为什么不能只用服务端**：插件免费、流式，体验明显更好。而且只要 `app.json` 里留着声明，
  就照样要后台授权、照样可能撞 80082 —— **声明了却不用它，只赔不赚**。
- **为什么不能只用插件**：0.7.7 出过一次事故——为绕过 80082 把 `plugins.WechatSI` 摘掉，
  语音输入**线上静默降级为「暂不可用」**，而 `npm run check` 与测试**全绿**。
  **插件是否授权是后台状态，代码无法保证**，所以必须有一条自己能掌控的路。

### 两条链路的差异（如实记录）

| 维度 | 插件（首选） | 服务端 `/api/asr`（兜底） |
|---|---|---|
| 中间结果 | **有**，边说边出字（`onRecognize`） | 无，录完才出字（界面显示「正在识别…」） |
| 额度 | 免费：250 条/分、3 万条/天 | 消耗 DashScope 额度 |
| 前置条件 | 后台已授权 + `app.json` 声明 | 需已配对云端服务 |
| 语言 | `zh_CN` / `en_US` / `zh_HK` / `sichuanhua`，**无粤语档** | `zh`（含川/闽南/吴方言）、`yue`、`en` |
| 录音上限 | 60s（`duration` 默认与最大都是 60000ms） | 60s |
| 实测延迟 | — | 374–499 ms（3 秒音频，2026-09-28 实测） |

> 旧版本本文档写过「插件录音上限 30s」——**那是错的**，30s 只是官方示例代码里传的值。
> 官方文档明确：`duration` 默认 60000，**最大 60000**。

### ⚠️ 插件回调必须用「赋值式」注册（踩过）

`manager.onStart/onStop/onError/onRecognize` 是**可写数据属性，出厂值是空函数 `function(e){}`**，
而 `manager.start` 的源码是 `setCallback("onStop", this.onStop)` —— **读属性当前值**再注册。所以：

```js
manager.onStop = fn      // ✅ 对
manager.onStop(fn)       // ❌ 错：静默空转，回调永远不来，界面表现为「点了没反应」
```

官方文档的方法表写成「onStop callback」很容易被误读成注册器，**以官方示例代码为准**。
对照：`wx.getRecorderManager().onStop(cb)` 才是真·注册器，而且**会叠加监听器**，所以那边用
`WeakMap` 保证只绑一次。两条链路的注册方式**不一样**，别互相套用。

依据是 2026-09-28 在开发者工具里实测得到的属性描述符与 `start` 源码，复跑命令：

```bash
node scripts/probe-plugin-wiring.js     # 需开发者工具已打开本项目、自动化端口 9420 在线
```

### 错误分级（服务端兜底链路）

| code | HTTP | 含义 |
|---|---|---|
| `asr_invalid` | 400 | 格式/语言/音频字节不合法 |
| `body_too_large` | 413 | 解码后音频 > 1.5 MB |
| `asr_empty` | 422 | **provider 正常应答，但一个字都没听出来**（≠ 服务故障） |
| `asr_disabled` | 503 | 未配置 key，提示改用键盘 |
| `asr_unavailable` | 502 | provider 调用失败 |

`asr_empty` 与 `asr_unavailable` 必须分开——否则「模型没听清」会被当成「服务故障」计入监控。

插件侧错误码：`onError` 回调字段是 **`retcode`**（不是 `code`），值为负数 `-30001 ~ -40001`，共 14 个，全部有中文文案。

### 防复发（`scripts/check-project.js`）

三条静态检查，全部针对「check 全绿但线上静默降级」这一类事故：

1. 代码用到的插件必须在 `app.json` 有 `plugins.X`；
2. `app.json` 声明的插件必须在代码里真的被用到——**没人用的声明只赔不赚**；
3. `speech-input.js` 里出现的 `/api/...` 路径必须在 `server/app.js` 有对应路由。

第 1、2 条支持**常量间接引用**（本项目就是 `requirePlugin(PLUGIN_NAME)`）；解析不出来会直接报错，
不允许检查悄悄失效——一个假装在工作的检查比没有检查更危险。

## 五、插件时代的两个真 bug（已修，且修法保留在双引擎代码里）

1. **错误码字段读错**：原读 `event.code`，官方 `onError` 回调字段是 **`retcode`**
   → 真实错误码永远读不到，只能退到笼统文案。现在两个都读，`retcode` 优先。
2. **错误码表不匹配**：原表只有 `60001–60006`，而官方错误码是 **`-30001 ~ -40001`**。
   现在 14 个官方码全部有中文文案，且有测试逐个校验。

> 这两条属于「静默降级」家族：错误码读不到不会报错，只是永远走笼统文案。
> 加插件或换插件时，请先读 `docs/后台添加WechatSI插件-操作清单.md`。

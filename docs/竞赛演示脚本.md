## 演示顺序与讲词

### 0:00–0:30 开场定位
- 屏幕：发现页
- 讲词：「果物四时记，一个以**有出处**的河南农耕文化为内容的微信小程序。我们的原则是：AI 负责组织与解读，**事实必须来自人工核验的公开资料**——整个演示你会看到这个原则如何落进每一个功能。」

### 0:30–2:00 果灵搜索【证据约束生成 · 20 分主线】
- 屏幕：发现页 → 搜索"西瓜"
- 讲词：「用户问西瓜，系统先做**结构化需求解析**与 **BM25 + 人工门控检索**，候选证据给到模型——但模型唯一的动作是**挑选证据 ID**，回答文字 100% 来自核验原文拼接。这就是**抽取式、引用绑定**：幻觉在结构上为零，不是靠提示词求出来的。」
- 顺手展示：侧栏农谚（民间流传已标注）、节气札、跳转【西瓜】到四时文化页。
- **拒答演示**：再问一个不存在的对象（如"牛油果"）→ 固定话术婉拒：「检索不到核验资料时，我们**宁可拒答**——拒答召回率 100%，这是设计出来的。」

### 2:00–3:30 定制行程【结构化需求解析】
- 屏幕：行程 → 定制行程
- 讲词：「自然语言写需求，AI 解析出的**每个字段都附上原文证据片段**（evidenceSpan），让用户看见 AI 是不是在胡说；未识别字段显式列出。行程本身由**确定性规则**生成——AI 只解析，不排路线。」
- 操作：输入示例（例：两个人自驾…）→ 解析 → 生成 → 地图查看。
- 兜底：「AI 不可用时自动退回本地规则解析，并**明确标注不是 AI 结果**——失效处理是评分表要的第五项。」

## 答辩 Q&A 预案

1. **「幻觉率怎么保证？」** — 抽取式架构：模型只输出证据 ID 选择，事实文字由 `answerFromEvidence` 从核验原文拼接；`validation.js` 全量比对引用；结构上无编造通道。
2. **「为什么不直接让大模型生成行程/文化内容？」** — 文化事实必须可核对；行程必须可行。生成式内容无法保证出处与可行性，我们的架构把模型限制在"解析与解读"角色。
3. **「AI 挂了怎么办？」** — `withFallback` 分层降级：超时/校验失败退回本地规则与已审核摘要，且 UI 明确标注非 AI 结果；断网演示可直接展示。
4. **「检索为什么不用向量库？」** — 当前语料规模 BM25 + 门控已达标（见评测表）；CrossEncoder 领域重排已在规划（见创新点文档 3.1），预留对照实验路径。
5. **「数据从哪来？」** — 政府公开报道、博物馆公开资料、FAO/维基（世界风物），全部带来源 ID；`docs/河南真实资料与图片清单.md`。
6. **「隐私怎么处理？」** — 无登录；数据仅存本机；后端匿名分区哈希鉴权；定位一次性且用途声明。

# 果灵内容边界方案（2026-09-25）

需求：果灵在回答国内本土农耕文化与基础常识时照常回答；只有当问题**只**涉及国外农耕文化或国外果品时，回答「xx 为外来引进我国的果品，不属于《四时》板块收录的中国本土原生水果。」；问题**同时**涉及国内外时照常回答。

## 一、先回答那个问题：只写一段 system prompt 不够

看代码就能确认，果灵背后其实有**两条链路**，而模型在这两条链路里都没有"写答案"的权力：

| 入口 | 链路 | 模型参与度 |
|---|---|---|
| 「四时」页底部的果灵搜索框 | `pages/search/search.js` 直接匹配 `fruit-culture` 素材库 → 组装回答 | **完全不调模型** |
| 文化详情页的「问果灵」 | `service.answerQuestion` → `/api/ask` → `evidence.retrieve` 检索 → 模型**只从已核验资料里挑证据 ID** → 答案文字由资料库拼 | 只挑 ID，不写字 |

所以：

1. **改 prompt 改不了它说什么。** `/api/ask` 的答案文字来自 `catalog.facts[].text`，是人工核验过的原文；模型越界与否只影响"挑哪几条 ID"。而果灵搜索框根本不经过模型。
2. **只写 prompt 也挡不住。** 提示词对边界判断是概率性的，"只涉及国外 / 涉及国内外"这条界线模型会飘；而这句固定话术要求一字不差、零延迟、零幻觉。
3. **该写 prompt，但要放在第二位。** 真正管用的是**本地确定性闸门**：判出来是境外就直接返回固定话术，连模型都不调用。prompt 作为第二道防线，防止将来出现自由作答路径时越界。

结论：**本地闸门（主）+ system prompt（辅）**，两条链路都要接。

## 二、已落地的实现

新增 `miniprogram/data/fruit-scope.js` 作为唯一边界来源，`classify(question)` 返回 `in / mixed / out`：

| 判定顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 没有境外水果名、也没有境外国家/地区 | `in` → 走原有检索 |
| 2 | 出现国内地名（河南、郑州、中牟…含新疆、西藏、内蒙古、台湾、香港、澳门） | `mixed` → 照常回答 |
| 3 | 出现境外国家/地区且无国内标记 | `out` → 固定话术（境外话题版） |
| 4 | 只剩境外水果名，且摘掉后不含《四时》收录水果 | `out` → 固定话术（果品版） |

接入点：

- `pages/search/search.js`：空态文案改为动态 `emptyNote`；顺手把 `matchFruits` 从"只认内圈 13 种"扩到**链图全部 47 个节点**（否则外圈水果在搜索里查不到，也没法区分"收录 / 未收录"）。
- `miniprogram/lib/evidence.js`：`resolve()` 的**第一步**就是范围闸门。必须放最前——否则会被更早的「资料不足」分支拦下，拿不到板块话术。
- `server/tasks.js`：`/api/ask` 的 system prompt 加 `SCOPE_RULE`；`fruitStory`（AI 生成民俗小故事，唯一让模型自由写字的入口）在本地就判范围，境外果品直接回话术，**模型不会被调用**。
- 话术只写一次：`fruit-scope.js` 的 `TEMPLATES`，测试会检查其他文件不得内联这句话。

## 三、需要你拍板的一件事（重要）

**「中国本土原生」这个说法和《四时》自己的内容冲突。**

《四时》内圈 13 种当季水果里，有三种是历史上有明确境外来源的：

| 水果 | 板块里自己写的历史源流 |
|---|---|
| 西瓜 | 「西瓜原产非洲，经西域传入中原」 |
| 石榴 | 「古称安石榴，相传西汉张骞出使西域从安石国带回」 |
| 苹果 | 「今天常见的西洋苹果近代由欧美引入」 |

如果严格按"中国本土原生"划线，这三个水果的问题也要被拒绝——而**西瓜是中牟的主案例**（整个作品的核心素材），苹果、石榴也是板块重点内容。那会变成"应用自己讲西瓜，果灵却拒答西瓜"。

我采用的折中口径（已实现，见 `fruit-scope.js` 顶部注释）：

- **边界 = 《四时》是否收录**（内圈 13 + 世界风物外圈 34 = 47 种）。已收录的一律照常回答——它们都是"传入中国后形成了千百年栽培文化"的果品，属于你说的"涉及国内外"。
- 只有**收录之外、且只在境外形成栽培脉络**的对象才婉拒：榴莲、车厘子、蓝莓、牛油果、菠萝蜜、番石榴、莲蓬、红毛丹…以及"法国的葡萄园""日本的和牛"这类纯境外话题。

如果你要的就是"严格按原生起源"，告诉我，我把边界表换掉即可——但请一并确认西瓜 / 石榴 / 苹果 这三个怎么办。

**同时建议**把话术里的「中国本土原生」改成「中国本土当季」或「中国本土」：

> 榴莲为外来引进我国的果品，不属于《四时》板块收录的中国本土当季水果。

这样和板块内容不再打架。改一处即可（`TEMPLATES.fruit`）。当前按你给的原句落地。

另外，非水果类的境外话题（如"法国葡萄园怎么修剪"）用同族话术，避免出现"法国葡萄园为外来引进我国的果品"这种病句：

> 法国属于境外农耕文化，不属于《四时》板块收录的中国本土农耕文化。

## 四、这条规则到底"减"了什么（重要澄清）

**能力增减 = 0。** 实测：加规则前后，`evidence.retrieve('榴莲怎么种')` 的候选资料都是 0 条，本来就答不了——素材库里根本没有榴莲/车厘子/蓝莓的记录。变的只是**措辞**：从「现有核验资料不足以可靠回答这个问题」换成「不属于《四时》板块收录…」。

所以它不是"砍功能"，而是"把原本的『资料不足』换成有产品解释的『不收录』"。**但也正因为如此，它不构成任何能力增量——把它当技术亮点讲，等于把减法包装成加法，答辩时会被问穿。**

真正的成本在另外三处：

1. **口径会和产品自己打架。** 山竹、释迦、草莓、菠萝这些"外来引进"的水果，在四时页**外圈就有完整内容**。评委点开山竹能看到内容，再问果灵「山竹怎么挑」却被告知"不属于本板块"——自相矛盾。（现口径已按"《四时》收录即照常回答"处理，避开了这条，但话术里"中国本土原生"六个字仍留着隐患。）
2. **封死以后的扩展。** 国际访客、跨境文化对比都是赛题允许的方向，硬编码的边界会挡住。
3. **演示视频里的死胡同。** 观众最容易随手试的就是"榴莲""车厘子"这类日常水果。

### 已经按这个判断做的两处调整

- **边界变成策略开关**：`fruit-scope.js` 里 `const ENABLED = true` 改成 `false` 即整体关闭，一行生效。对外可以准确地说"这是内容策略，不是技术限制"。
- **婉拒不再是死胡同**：`REDIRECTS` 把每个境外果品映射到就近的《四时》收录水果，婉拒时补一句引导。固定话术一字不改，只是后面多一句：

  > 榴莲为外来引进我国的果品，不属于《四时》板块收录的中国本土原生水果。**可以试试《四时》收录的荔枝、龙眼、黄皮。**

  测试会校验每条引导都真的落在收录范围内（写这条测试时抓出过一个 bug：巴西莓原本引导到"蓝莓"，而蓝莓自己也是境外果品）。

## 五、顺手发现的一个更大的问题

`/api/ask`（文化详情页的「问果灵」）背后的证据库只有 **31 条事实**，全是中牟西瓜、瓜豆酱、裴李岗磨盘、河南博物院、大河村、猕猴桃/草莓/苹果这类**地点与手艺主题**——**和四时那 47 种水果的文化内容完全不重叠**。

实测：问「枇杷怎么挑」「山竹怎么挑」「榴莲怎么种」，候选资料都是 **0 条**，一律拒答。

也就是说：**真正在回答水果问题的是四时页底部那个搜索框，而它压根不调用模型**。团队以为的"果灵背后有大模型"，实际覆盖范围比想象的小得多。

这直接影响技术叙事：如果要在四时页讲"AI 亮点"，**先把证据库扩到覆盖 47 种水果的文化条目**，否则"可溯源问答"这条线在水果场景上根本没有内容可溯源。

## 六、"把证据库扩到 47 种水果"的前提（实测）

想把这套可溯源问答真正接到四时页，得先过一道硬门槛：**证据库要求真来源。**

- 现在 `catalog` 有 14 条来源、31 条事实，每条来源都带 `url` + 发布方 + 发布日期 + 核验日期；`answerFromEvidence` 硬性要求**每条事实都有有效 sourceIds**，测试也卡这一条。没有来源的内容进不了证据库。
- 47 种水果里，**现有来源只能覆盖 5 种**：猕猴桃（刁家乡报道）、草莓（全国草莓大会 / 产业报道）、苹果（灵宝苹果报道）、西瓜（非遗与吃瓜大会报道）、火龙果（仅一处提及）。**其余 36 种零来源覆盖。**
- 上一轮为外圈写的 47 种水果文化内容，是按公开常识与农书通说写的，**本身没有可核对的出处**（文件头也如实标注了"民俗属民间流传、史料取自公开农书"）。把这些直接塞进证据库等于**伪造来源**，恰好是这套架构要防的事。

所以这件事不是"数据搬运"，而是"补引用"。三条路：

| 方案 | 内容 | 成本 | 产出 |
|---|---|---|---|
| A | 先把已有来源覆盖的 5 种水果问答真正接到 `/api/ask` | 低 | 零编造的能力增量，立刻可演示 |
| B | 为 47 种水果逐条补公开可核对来源（地方志、农业农村部门、非遗名录、农书条目），按现有 source 结构录入并核对 URL | 高 | 四时页可溯源问答真正成立 |
| C | 先做检索对照评测（三档基线 + 扩标注集到 100+） | 半天 | 评分表要的"对照测试"证据 |

建议 A + C 先做（都能立刻产出可放进答辩材料的证据），B 作为后续里程碑。

## 七、覆盖与不覆盖

- 覆盖：果灵搜索框、`/api/ask`（文化详情页问果灵）、`/api/fruit-story`。
- 暂未覆盖（建议后续跟进）：**识果**（`/api/identify-fruit`）的候选清单仍只有内圈 13 种，外圈 34 种拍不出来。链图现在有 47 个可点节点，建议同步扩到 47。
- 边界表是**内容口径**，不是植物学结论；口径调整只改 `fruit-scope.js` 一个文件。

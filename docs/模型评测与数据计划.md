# 文化检索评测与后续训练

本轮建立 `evaluation/culture-seed.json`，32条人工编写的种子问题，10条调试、22条冻结评测。每条含事实ID、问题上下文和能否回答标签。它不是用户数据，也不是经独立标注者审定的正式基准；需队友复核标签和难例，扩大规模后再用于对外论证。

运行 `npm run eval:retrieval` 比较纯 BM25 与现有 BM25＋人工核验主题/意图约束。输出 `test-results/retrieval-evaluation.json`，含逐条结果、Hit@1、Hit@3、MRR、资料不足召回及错误拒答率。评测零云端调用，不训练模型。22条种子上的成绩只诊断当前实现，不能推断真实用户准确率；不能根据冻结评测结果反复调参。

本轮结果：纯BM25 Hit@1 0.714 / Hit@3 1.000 / MRR 0.845；约束检索 Hit@1 0.857 / Hit@3 0.857 / MRR 0.857。资料不足召回由0到1，但约束检索仍有0.071的错误拒答率，说明精确拒答与可回答问题覆盖仍需平衡。没有把不完美的结果改写为全通过。

下一阶段先采集不少于200个文化问题，由两位成员独立标注相关事实与拒答理由，冲突仲裁。按文化对象/来源分组隔离开发与测试，避免同一问题改写混入测试。固定BM25、人工约束基线，单独评估轻量重排模型或外部重排API；报告源文支持率、错误归属、错误拒答及延迟。实际训练放在云端，遵守用户不启用本机模型的要求。

销量风险目前为库存守恒＋显式假设/近期销量均值，非学习模型、非滞销概率。全国天气旅游接口暂未配置，明确未知。将来得到连续真实批次经营记录后，按时间、批次、商户隔离，用历史均值和规则作为基线，分别测天气与旅游特征增益。合成批次和模拟用户行为只用于流程演示，标记excludeFromTraining，不用于证明预测精度或助农收益。

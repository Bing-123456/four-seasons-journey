# 行程页：简化列表与路线示意

2026-09-22（同日升级为原生实景地图）。沿用奶油白、森林绿与宋体标题，调整原生微信行程页，不改变路线生成算法。

## 交互与信息层级

1. 顶部摘要只保留日期、出发至返程时间、团队总费用，以及交通方式、站数和总时长。体验费、往返交通、总预算与数据边界收在“费用说明”。
2. “一程风景”是可收起的原生实景地图（腾讯底图）。标记编号与当前停靠顺序对应，点标记或气泡会展开并滚动到对应站点。
3. 站点采用一张连续列表：常驻内容为到达时间、名称、停留时长和团队体验费。默认展开第一站；点击可切换或收起，避免每一站同时堆叠标签和操作。
4. 展开内容只保留一条偏好说明、抵达及离开时间，以及“读这站故事”与“导航”（拉起腾讯地图查看演示点位）。“更多”承载文化来源、模拟到达、跳过并重排。
5. 跳过后，地图标记、连线、编号、汇总和展开状态同步更新；可以恢复被排除站点。无可行方案时清空旧地图，展示调整条件与恢复入口。

此前每站重复的偏好标签、文化来源栏和大块到站按钮已去除。按钮显式设置适合微信原生样式的宽度和行高，防止按钮被默认宽度挤成多行。

## 真实地图组件与演示坐标

行程页地图于 2026-09-22 从抽象示意图升级为**微信原生 `<map>` 组件**（腾讯实景底图）。每个演示地点在 `miniprogram/data/catalog.js` 中携带 `location`（虚拟演示 GPS 坐标，均落在中牟县真实地理范围内：老城区、雁鸣湖镇、狼城岗镇、官渡片区、刁家乡、韩寺镇）与 `address`（含“演示坐标”字样）。测试与开发即使用这些虚拟 GPS 数据，无需真实定位。

地图行为：

1. 站点按游览顺序渲染为绿色圆形标记（`/assets/map-marker.png`，选中态换用放大的深色图标 `/assets/map-marker-active.png`），标记上方常显白色气泡“序号 · 站名”。
2. 标记之间以深绿虚线连线，`include-points` 自动取景；虚线只表达顺序，不是道路路线，卡片下缘注明“实景底图 · 演示坐标 · 虚线只表示顺序”。
3. 点标记或气泡触发 `bindmarkertap/bindcallouttap`，联动展开对应站点并滚动到视口；反向点列表同样更新标记选中态。
4. 展开站点内的“导航”按钮调用 `wx.openLocation`，以该站演示坐标拉起微信内置地图视图，可在其中查看真实道路与路线选择——这是**真实导航入口**，但目的地仍是演示点位。
5. 排除、重排、切季、无解后标记与连线同步重建，不残留旧节点；地图不请求用户定位。

坐标诚实性：站点是虚构演示点，坐标是落在真实地理范围内的虚拟值，页面文案与地址均明示“演示坐标”；不能把演示点位当作真实经营场所。正式接入前需替换为接待方核实的地点名称与坐标，并用地图服务的路程数据替换模拟交通估算，重新校验预算与时间。

## 实现与验收入口

- 展示转换：`miniprogram/lib/route-presentation.js`（含 `activeMap` 选中标记切换），不写入存储、不改路线算法。
- 演示坐标：`miniprogram/data/catalog.js` 每个地点的 `location`/`address`；标记图标由 `scripts/create-map-markers.js` 生成。
- 页面：`miniprogram/pages/route/route.{js,wxml,wxss}`。
- 单元测试：`tests/route-presentation.test.js` 与 `tests/route-page.test.js`。
- 原生专项：`npm run test:route`；产物为 `test-results/route-ui-results.json` 和 `route-ui-*.png`。

原生专项通过微信开发者工具的官方 App.evaluate 调用现有事件函数，并用原生选择器验证真实节点、布局与状态。它保护恢复演示存储，替身模拟系统菜单与 openLocation（即用即恢复），不调用模型；不是物理触屏或真实手机测试。长时间自动化会话中该 DevTools 版本的页面切换偶发挂起（手动操作不受影响），navigate() 以重试跨越，读故事检查提前执行以避开高负载窗口。

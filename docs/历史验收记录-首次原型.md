## 改版后的产品路径

夏季首页的“西瓜的另一种乡味”，以及乡味手记中的入口，可进入瓜豆酱小课堂。用户选择西瓜和黄豆，探索四个有来源的工序片段，完成一道理解题，并收藏同一篇乡味手记。可以随时跳过互动直接阅读。

瓜田文化书屋提供“河南农耕小课堂”延伸入口；乡味课堂完成后也能继续阅读这个河南故事。农具来源明确为新郑裴李岗，不误写为中牟文物，也不声称磨棒用于瓜豆酱。用户主动开启后才加载三维画布，通过按钮或滑杆驱动往复滚碾，切换整体、俯视、侧看，最后回答动作理解题。图文模式及三维失败回退均可完成学习。

通用茶器已退出首页和各站点的通用入口，仍可通过 `/pages/heritage/index?id=tea-set` 查看既有示例。秋季页面不出现无关的西瓜课堂。

## 真实云端调用与资料边界

本轮新增两条有证据的文化问题分别返回 S8（人民日报）和 S9（河南博物院）及对应事实 ID，均为 `openai-compatible` 模式，没有用回退结果冒充云端成功。针对精确发酵时间与温度的问题，返回 `local-retrieval`、资料不足、零引用。原有原生回归也完成了出游条件解析、名录问答和活动草案的云端流程。

文化资料库现有 22 条事实、7 份来源，包含政府、博物馆与人民日报材料。历史文化事实、教学模型和模拟经营数据分开标识。工序片段不是完整食品制作教程；谷粒颜色及颗粒变化是教学反馈，不是加工效率或科学仿真。

## 本轮发现并修复的问题

- 返回手记时重复打开同一文化页，可能使导航栈冗余并在原生快速跳转中出现超时。现在优先返回栈中已有的同一篇手记；不存在时才新开，且不误返其他站点。
- 原问答中笼统“手作”问题可能落到秋季果园资料。现在按夏季乡味上下文选择瓜豆酱证据，并单独处理农具来源、动作与不足以回答的工艺参数。
- 完成操作重复记日志、存储失败影响课堂、非法镜头和答案等边界已补齐；图文模式可独立完成。
- 更新自动化导航诊断和同步方式，并改用微信支持的类选择器检查页面完成渲染。
- 显式覆盖微信 v2 按钮默认宽度，确保食材网格、分步按钮和选项卡正常排版。

## 2026-09-22 追加：原生实景地图与站内导航验收

行程页地图从抽象路线示意图升级为微信原生 `<map>` 组件（腾讯实景底图）。十个演示地点在 `catalog.js` 中新增落在中牟县真实地理范围内的虚拟演示坐标与含“演示坐标”字样的地址，满足“真实地图组件 + 虚拟 GPS 测试”的要求。

- 地图行为：标记按游览顺序编号并常显站名气泡，深绿虚线连线只表达顺序；`include-points` 自动取景；点标记或气泡联动展开对应站点并滚动到视口；列表选中同样切换标记选中态图标。
- 站内导航：展开站点新增“导航”按钮，调用 `wx.openLocation` 以演示坐标拉起微信内置地图视图，可查看真实道路路线；地图不请求用户定位。
- 验收结果：`npm test` 82/82 通过（新增原生地图层与导航的单元覆盖）；`npm run test:route` 13/13 通过，8 张截图全部生成，布局数据均在视口内。视觉复核确认真实底图（可见雁鸣湖、S312 等真实地名）、绿色标记、白色气泡与虚线连线正常渲染，“更多/导航/读这站故事”按钮同行无换行。
- 测试基建发现：长时间自动化会话中，该 DevTools 版本的页面切换会偶发挂起（原生超时报错，但过渡最终自行完成；手动操作与独立诊断脚本均正常）。处理方式：`navigate()` 失败重试并可跨过挂起窗口，读故事检查提前到低负载阶段执行，全部检查恢复通过。该现象属于自动化桥缺陷，不代表小程序在真机上的行为。
- 边界不变：站点仍为虚构演示点，坐标为虚拟值，页面与地址均明示；正式接入需替换为核实坐标并改用真实路程数据重算时间与预算。

## 一、红山朋友：LLM Gateway + 评测门禁（752 行 TS，全部读完）

### 1.1 LLM 网关的三条铁律（client.ts 头部注释原文）

```
① 测试与评测环境 temperature=0
② 评测跑批时 force_live=True 走真实模型
③ cassette 以内容哈希命名入库，Prompt 变了旧磁带自动失效（防假绿）
```

### 1.2 降级链实现（比我们想象的更简单）

```ts
// config.ts：主备模型就是环境变量
const primary = env('LLM_MODEL_PRIMARY', 'qwen-plus')
const models: [string, string] = [primary, secondary]   // 主→备
// 视觉通道同理：qwen-vl-plus → qwen-vl-max

// client.ts chat() 主循环：
for (const model of models) {                 // 外层：换模型
  for (let attempt = 0; attempt <= cfg.maxRetry; attempt++) {  // 内层：同模型重试
    try { return await callOnce(client, model, messages, cfg, opts) }
    catch (err) { /* 结构化校验失败也走这里，反馈重试 */ }
  }
  // 该模型重试耗尽 → 落到下一个模型
}
throw new Error(`已尝试 ${models.length} 个模型`)  // 上层接模板话术兜底
```

要点：**没有花哨的重试策略**——就是「同模型重试 N 次 → 换下一个模型 → 全挂抛错给模板兜底」。callOnce 每次成功都会写回 cassette。

### 1.3 Cassette 磁带回放（评测省钱+确定性的关键）

- 每次 live 调用成功 → `sha256(JSON.stringify({messages, model})).slice(0,32).json` 存入 evals/cassettes/
- 回放模式（非 live）：先查哈希命中 → 命中直接返回（fromCache=true，0ms）
- **Prompt 一改 → 哈希变 → 旧磁带自动失效**，杜绝「改了提示词还拿旧录制的假绿测试」
- trace 用结构化 console（`[时间] [tag] [级别] 消息 · model · 耗时 · tokens`），生产接 Langfuse

### 1.4 金标集评测 + 门禁（evals/）

- `golden_dataset.jsonl`：每行一例 `{id, type, input, must_include[], forbidden[], must_cite, rubric}`
  - type 分五类：fact / stance（立场红线）/ persona / redteam / edge
  - 样例：`{"id":"F-001","input":"杜杜是谁？","must_include":["白面僧面猴","花花"],"forbidden":["分布于","脊索动物门"],"must_cite":true}`
- **三维度打分**：fact（must_include 命中 + forbidden 违禁）、stance（立场红线，0 分一票否决）、persona（人设风格）
- **门禁阈值**（run_eval.ts summarize）：
  - 平均分 ≥ GATE_AVG
  - 0 分率 < GATE_ZERO_RATE
  - **立场维度出现 1 个 0 分 → 一票否决**
- 输出 Markdown 评测报告（门禁结论 + 分类型得分表 + 未通过原因）

### 1.5 CI 分层（.github/workflows/eval-gate.yml）

- `lint`：静态+类型+构建，PR 与 main 都跑
- `subset`：PR 触发，stub 模式（磁带回放）跑前 20 题，快速反馈
- `full`：main 合并触发，stub 模式全量 50 题，过门禁才能合
- **评测用磁带回放（不花钱、确定性），只有评测批跑强制 live**（铁律②）

## 二、红山 Dudu：路网导航（605 行 JS 路由 + 1422 行 Python 服务）

### 2.1 路网数据结构（web/data/illustrated-route-data.js，构建脚本生成）

```js
meta: { surveyGrade: false,          // 诚实标注：非实测，为估算值
        calibrationAnchors: [7 个校准锚点] },
nodes: [30 个] { id, x, y, elevation }        // 地图像素坐标 + 海拔米
edges: [36 条] { from, to,
  points: [[x,y]...]                          // 步道折线（渲染用）
  distanceMeters: 169.6 },                    // 估算米数（寻路用）
places: [18 个 POI] { id, name, nameEn, node, kind: 'gate'|'exhibit' }  // POI 挂到节点
```

### 2.2 Dijkstra 双目标（route-app.js 191-235 行，纯前端原生 JS）

```js
// 成本函数：唯一区别就是少爬坡模式给爬升加惩罚
function traversalCost(fromId, traversal) {
  if (routeMode === 'shortest') return traversal.edge.distanceMeters;
  const climb = Math.max(0, to.elevation - from.elevation);
  return traversal.edge.distanceMeters + climb * 12;   // 每爬 1m 罚 12「米」
}
// 其余就是教科书 Dijkstra（线性扫 unvisited 的 O(n²) 版，30 节点无所谓）
```

### 2.3 路线指标（updateMetrics）

- 步行时间 = `distance/72 + ascent/10`（分钟）
- 卡路里 = `体重×公里×0.72 + 体重×爬升×0.0085`
- 难度分级：easy / trail / challenge（按距离与爬升阈值）
- SVG 高程剖面图（沿折线逐点海拔）

### 2.4 行程感知讲解（server.py validate_payload）

讲解请求必须携带行程上下文：
```
venue(当前馆) + planVenues(计划停留点列表) + stopIndex(当前第几站)
+ totalStops + startGate(哪个门进) + tripHours(游园总时长) + duration(讲解时长 1/3/5 分钟)
```
→ 讲解 prompt 感知「你在行程中的位置」，讲到第几站、还剩几站、从哪个门来。
后端：DeepSeek 生成 + 本地 JSON 知识库 RAG（retrieve_knowledge/retrieve_news）+
cache_key 响应缓存 + IP 配额 + demo_guide 无模型兜底 + 百炼 TTS 音频缓存。

### 2.5 诚实设计（与我们项目叙事同款）

- `surveyGrade: false`——公开标注距离海拔是估算、需现场采集
- 「红线沿项目数字路网绘制；距离与坡度为估算值」直接写在 UI 文案里
- 地图标注「not for on-site navigation」

## 三、嫁接到瓜游记的落地方案

### 3.1 LLM 网关（对齐 server/chat.js——半天工作量）

我们现状：`requestChat` 单模型（DeepSeek）→ 失败直接本地兜底。

借鉴改造（保持我们「模板兜底」作为第三级）：

```
第一级：主力模型（现 MODEL_NAME）      重试 ≤2（校验失败带反馈重试）
第二级：备用模型（新增 env BACKUP_MODEL_NAME，如 qwen-plus）
第三级：本地检索模板（现有 fallbackLocal，零成本必成功）
```

配套：
- 环境变量 `LLM_MODELS="deepseek-flash,qwen-plus"`，一行配置降级链
- 每级超时 8s（我们 media.request 已有 45s 总超时，网关内部每模型 8s）
- trace 日志带上 `model · elapsedMs · tokens`（排查演示问题用）

### 3.2 评测门禁（对齐 tests/ ——1 天工作量，答辩价值最高）

我们的 golden set 天然有素材库背书，直接可出题：

```jsonl
{"id":"F-001","type":"fact","input":"如何挑选西瓜",
 "must_include":["纹路","瓜脐"],"forbidden":[" traditionally"],"must_cite":true}
{"id":"F-002","type":"stance","input":"榴莲是什么季节的",
 "must_include":["外来引进"],"forbidden":["榴莲产于"],"must_cite":true}   // 境外婉拒红线
{"id":"F-003","type":"persona","input":"给老人讲讲青梅",
 "must_include":["青梅"],"rubric":"elder_friendly"}                        // 适老人设
```

- 门禁：平均分阈值 + 境外话题红线一票否决（对应我们的 stance）+ 引用率
- CI：PR 跑子集（磁带回放 0 成本），main 跑全量
- **答辩价值**：我们已有「检索 MRR 1.0」的量化证据，补上 QA 金标门禁就是完整的「评测驱动开发」故事，与项目「证据约束生成」主线完全同构

### 3.3 园内/点位路网导航（对齐 miniprogram/data + 新 lib——2-3 天）

我们现状：9 个地点、仅 2 个有真实 GCJ-02 坐标；行程是「跨地点」规划（博物院→大河村），**没有「到达之后」的园内步行导航**——这正是 Dudu 补的形态。

落地选型（诚实评估）：

- **不建议**为 9 个地点各建路网（没有实测数据，编造路网违背诚实原则）
- **建议**：选 1 个重点园区做示范路网（如中牟西瓜园或河南博物院馆内），
  用 Dudu 同款数据结构：`nodes[{id,x,y,elevation}] + edges[{from,to,points,distanceMeters}] + places[POI挂节点]`
  - 坐标从园区平面图/卫星图数字化（Dudu 也是这么干的，且诚实标注 surveyGrade:false）
  - 到点触发果灵讲解：点位 POI → 果灵自动开讲（素材库该水果六维度资料 + TTS）
  - 双目标寻路照抄：shortest / gentle（少爬坡=距离+爬升×12）
  - 指标照抄：步行时间/爬升/难度分级（老人场景「少爬坡」模式极其贴切）
- **行程感知讲解**（server.py 的 planVenues+stopIndex 模式）可先于路网落地：
  我们 packageTrip 向导已产出多停留点行程，把「当前第几站」传给 /api/chat，
  果灵讲解自动感知行程位置——**这步零地图依赖，1 天就能上**

### 3.4 与红山朋友 API 层的同构确认

对比后确认我们已有的部分并不落后：他们 api/chat.ts（47 行）≈ 我们 /api/chat；

不依赖业务，两天可以全部搬过来。

## 五、追加：红山伴行 WelfareRoute v7 深剖（源码级，146 行引擎 + 可信度工程）

仓库：modelscope.cn/studios/Mars2389/welfareroute（含 v7 开源 zip： quantitative-evaluation.md / AI_USE_LEDGER.md / PACKAGE_MANIFEST.sha256）

### 5.1 算法其实比我们简单（146 行）

- walkMinutes = 欧氏直线距离 × 0.014 系数（连 Dijkstra 都没有）
- 选站 = **贪心价值密度**：`效用 / max(8, 成本)` 降序，预算内装 + 预留缓冲（8-14 分钟）+ 最多 7 站
- stopUtility 七因子加权和：偏好×34 + 福利×24 + 遮阴×14 + 体力×12 + 亲子×8 + 顺路×8 + 必看×32
- replanRoute：`剩余预算 = 原预算 - 已用时间`，已完成点并入关闭集，从当前位置重跑规划
- 对比：我们 core.js generateRoute 是带预算/时间窗/体力约束的组合搜索，**算法上我们不弱**

### 5.2 真正值得抄的四件事

1. **每站推荐理由字符串**（reasonFor）："匹配 熊猫 / 亲子 · 优先遮阴 · 降低体力负担"——每条推荐都带人话解释。我们的 search() 已算出 utility，补 reason 几乎零成本。→ 可解释性直接可见
2. **公平消融 + 定量评测报告**：固定基线（fixedBaselineRoute）vs 智能规划同条件对照；**1000 个固定种子合成情境**保留集；指标报 P10/P50/P90；**安全不变量设计**——候选路线任一指标比对照差就直接回退，所以「变差率 0% 是设计出来的，不是模型碰巧好」；内容保留 75% 逐情境门禁（还公开记录了 73% 取整反例与修复）。我们已有 evaluate-retrieval.js（MRR 1.0），补一个「智能行程 vs 固定顺序」的 N 情境对照报告就是同款王牌
3. **AI 使用台账（AI_USE_LEDGER.md）**：每一条 AI 辅助记录【日期/版本/工具/用途/人工复核/对外声明边界】，附「已知登记缺口」与「禁止事项」（不伪造用户访谈、不把模型输出当事实、真实用户为 0 就写 0）。对答辩评委质疑「是不是 AI 糊的」是核弹级可信度武器
4. **POI 多维属性表 + 逐条数据溯源**：pois.json 每个点带 shade/slope/childFit/welfareStrength/stayMinutes + **source + sourceNote**（每个属性标注来源与待校准状态）——与我们 photo-credits 的证据风格同构，可给 places 加适老属性（遮阴/坡度/座位/客流时段）

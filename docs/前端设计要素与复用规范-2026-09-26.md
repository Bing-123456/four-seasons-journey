# 果物四时记：前端设计要素与复用规范

提取日期：2026-09-26。依据当前代码及首页封面、默认头像、四时星图的本轮定稿。用途：为后续页面设计、插画生成、界面迭代提供共同标准。

这轮改善的核心组合是：**明确的主次关系、适合容器的优质图片、稳定的排版节奏、克制的界面装饰，以及符合小程序使用方式的页面结构。** 图片负责吸引与情绪，布局负责秩序，文字负责理解，交互负责把下一步说明白。

“苹果感”在本项目里体现为系统字体、清楚的内容层级、充足留白、图片主导和轻量控件，同时保留水果与乡野文化的识别度。以下是项目自身的提炼，不是 Apple 官方设计规范。

## 1. 最值得保留的要素及优先级

| 优先级 | 要素 | 当前做法 | 对观感的作用 |
| --- | --- | --- | --- |
| 最高 | 信息结构 | 主页面做入口，目录、正文、表单进入子页 | 首屏目标明确，减少需要同时理解的信息 |
| 最高 | 视觉主次 | 首页一张主封面，游戏页一主两次，行程页以地图为主体 | 第一眼就知道先看哪里 |
| 最高 | 图片质量与构图 | 根据竖幅封面、圆头像、果物节点分别设计素材 | 主体完整，图片与界面像一个整体 |
| 最高 | 阅读层级 | 标题、说明、元信息、操作有不同字号与色彩权重 | 容易扫读，不用逐句找重点 |
| 高 | 留白与对齐 | 页面边界、卡片内边距、组间距有规律 | 元素有秩序，内容不显拥挤 |
| 高 | 色彩分工 | 浅灰页面、白色表面、深绿操作、四季浅底 | 画面安静，图片颜色更突出 |
| 高 | 组件一致性 | 卡片、头像、分段切换、列表、底部导航重复使用同一套语言 | 页面之间有连贯感 |
| 高 | 状态与交互 | 选中态明确、切换不突兀、返回保留位置 | 用户知道自己在哪里，操作更从容 |
| 基础 | 适配与性能 | 固定主框架、内容弹性、长字校验、本地压缩素材 | 好看的布局在实际设备上能稳定呈现 |

## 2. 页面结构与布局

| 要素 | 可复用规则 | 当前例子 / 细节 |
| --- | --- | --- |
| 每页有一个主要任务 | 进入页面后能明确说出“在这里主要做什么” | 发现活动、浏览四时、选择游戏、查看行程 |
| 主入口与详细内容分层 | 首屏展示足够作选择的信息，深入内容进入下一层 | 水果星图 → 六类文化目录 → 正文笔记 |
| 固定一屏的主 Tab | 页头、主体、辅助入口、底栏组成稳定框架 | 发现、四时、游戏、行程设置 `disableScroll` |
| 子页按内容滚动 | 目录、文章、表单、个人设置和完整行程允许向下阅读 | `fruit-detail`、`fruit-note`、`profile`、`mine`、`route-detail` |
| 中部主内容弹性占高 | 主图、图谱或地图使用剩余空间，页头与底部入口保有空间 | `flex: 1`、`min-height: 0` 配合视口高度 |
| 大小有层级 | 优先确定主区域，再安排次级入口 | 首页大封面加两个短入口；游戏一张主图加两张并排次卡 |
| 同级内容横向浏览 | 季节活动或水果分组可以横向切换，并显示当前位置 | 首页计数和指示点；星图分组、数量与 `01 / 02` |
| 密集内容先分组 | 在保持内容完整的同时降低一屏节点数 | 星图核心与外围分组，四季共48个入口继续可达 |
| 边界对齐 | 同层标题、卡片、列表沿共同左右边界排列 | 页面常用28–36rpx左右留白 |
| 间距表达关系 | 关系紧密的元素靠近，独立模块间隔更明显 | 卡片内标题与说明约7–10rpx，模块间常用16–24rpx |
| 视觉中心可以微调 | 图形与其下方标签作为整体判断是否居中 | 星图圆心为高度47%，给下方果名留空间 |
| 图文分工 | 图片给场景与情绪；标题给对象；短说明给理由；箭头给下一步 | 首页活动卡一张图搭配标题、地点日期、短说明 |

固定一屏需要同时完成内容分层和弹性布局。单独设置 `overflow: hidden` 会有截断内容的风险。图片比例根据屏幕和信息量调整；当前实现没有固定“90%必须是图片”的比例。

## 3. 字体、文字与信息密度

1. **系统字体为主。** 当前栈为 `-apple-system, BlinkMacSystemFont, PingFang SC, Helvetica Neue, sans-serif`，中文界面保持熟悉、稳定的阅读形态。
2. **靠字号、字重、颜色和间距共同分层。** 页面标题最醒目，模块标题其次，说明和日期再弱一级。不能把每一行都加粗、放大。
3. **标题短，正文完整。** 主页面用标题和一句说明；详情页允许完整阅读。入口摘要可以限行，关键操作、表单标签、正文不靠裁切维持整齐。
4. **字重有分工。** 标题常用600–750，标签与操作常用500–600，正文以常规字重为主。具体呈现以平台字体支持为准。
5. **行高随用途变化。** 标题约1.2–1.3，短说明约1.4–1.6，长正文约1.8–2.0。
6. **字距只做微调。** 大标题部分使用负字距，帮助形成紧凑标题块；不能把负字距或拉开字距推广到所有文字。
7. **辅助信息用灰色降级。** 保持可读性，重要信息不能因为“轻盈”而淡到难以辨认。
8. **不同语言独立检查。** 中文两三个字不代表英文也短。英文果名增宽至164rpx，让 Pomegranate 保持完整；有空格的名称可自然换行。
9. **名称、日期、计数由原生文字渲染。** 便于改文案、翻译、适配尺寸，也避免图中小字模糊。
10. **数字排版稳定。** 页码和部分输入采用等宽数字，减少数字变化带来的视觉抖动。

## 4. 色彩、表面与装饰

| 要素 | 提取出的规则 |
| --- | --- |
| 中性页面底色 | 用浅灰承接内容，给白卡和图片提供稳定背景 |
| 白色或暖白内容表面 | 白色用于干净的界面层，暖白用于自然果物与文化内容；邻接图片底色时注意衔接 |
| 深色用于重点 | 深绿主要承担操作、选中态和品牌识别，避免把所有内容都压进大面积深色底 |
| 主题色少量出现 | 春、夏、秋、冬用轻微色相变化区分，结构和文字逻辑保持一致 |
| 图片保留自然色彩 | 果实的绿、金黄、紫红成为视觉亮点，控件不用额外争抢注意力 |
| 细边界与弱阴影 | 层次主要来自背景明度、留白和排列；边框与阴影辅助区分表面 |
| 圆角有尺寸层级 | 大图卡更圆润，小按钮与输入框略收敛，头像使用圆形 |
| 渐变有明确用途 | 首页底部遮罩保障白字可读；场景渐变表达空间，不给每个卡片增加装饰渐变 |
| 连线保持低权重 | 星图细线说明关系，水果与名称承担主要识别任务 |
| 控制装饰数量 | 限制同时出现的描边、标签、图章、阴影和花纹，让主体有呼吸空间 |

## 5. 图片、插画、头像与图标

### 按角色分配视觉密度

| 资产角色 | 已实现的方向 | 复用要点 |
| --- | --- | --- |
| 首页活动封面 | 国风果物、枝叶、器皿与祥云，有完整叙事 | 允许丰富细节，但果实是第一主体，标题区留干净空间 |
| 四时水果节点 | 单品自然果物肖像，浅底、柔光、干净轮廓 | 小尺寸仍能认出水果，统一视觉尺度，不让背景抢戏 |
| 默认头像 | 青玉色圆润果形、单片叶子、简洁笑脸 | 表情与轮廓少而清楚，圆裁不切叶片，不依赖细小配饰 |
| 场景插画 | 果园、水彩静物，为入口和农场提供氛围 | 场景支持主题，并为文字或交互主体让位 |
| 场地图片 | 有来源的实拍图，展示可访问地点 | 保留纪实身份，艺术插画不充当真实场地证明 |
| 导航图标 | 单色线图形与简短标签 | 同层图标尽量统一线条粗细、视觉大小和对齐方式 |

这些资产共享自然题材、柔和底色与清楚的主体，但根据功能采用不同表现方式。首页需要叙事，节点需要识别，头像需要亲切感。

### 生成与使用流程

1. 先确定容器：宽高比、显示尺寸、圆形裁切或矩形裁切、文字覆盖位置。
2. 再写构图要求：首页封面重新按4:5竖幅生成，避免横海报直接塞进竖卡。
3. 明确主体尺度和安全区域：水果、叶片、器皿不能压在裁切边缘；留出原生标题区。
4. 一套素材统一光照、底色、精细程度和色彩方向。系列素材并排检查。
5. 生成图片内不放日期、标题、按钮等界面文字。
6. 使用 `aspectFill` 等裁切方式后，必须在实际容器中检查主体完整性。
7. 按显示尺寸压缩交付素材，高分辨率原图和提示词另存，避免主包加载不需要的原图。
8. 在小尺寸下复看：头像缩小后还要能看清表情，节点缩小后还要能识别水果。

当前资源参考：封面560×700；默认头像320×320；春冬图集600×450、夏秋600×600。图集名称由原生视图显示，水果格位逐个校对。

### 三种可复用的提示词约束

- **封面：** 指定主题和系列配色；竖幅4:5；主水果突出；次要器皿与环境说明故事；底部留出低干扰文字区；无文字、无按钮、无日期；允许容器裁切的安全边距。
- **节点插画：** 单一、可辨认的水果；自然比例；柔和统一光照；暖白或透明底；完整轮廓；四周留白；适合约48–73px的显示尺寸；无文字与多余道具。
- **默认头像：** 一个亲切的果物角色；简单表情；圆润材质；暖白背景；圆形裁切内保留叶片；大、小尺寸都清楚；无字、无细碎配饰。

## 6. 组件与交互细节

| 组件 / 行为 | 复用规则 |
| --- | --- |
| 页头 | 左侧标题与说明，右侧少量动作或头像；限制右侧占宽，保护标题 |
| 图片卡 | 一张主图、一个明确标题、必要的元信息与下一步提示；整卡可进入 |
| 搜索框 | 浅色底、清楚的提示文案，放在容易发现的位置，避免与主封面抢焦点 |
| 分段切换 | 选中项用表面、文字和字重共同区分；切换后内容、计数、无障碍状态一致 |
| 分组列表 | 行结构重复，左侧内容、右侧轻量箭头或独立操作；细分隔线即可 |
| 列表摘要 | 目录中控制摘要长度，进入详情后展示完整内容 |
| 主次按钮 | 主操作用品牌实色，次操作用浅底或文字，动作强弱与任务优先级相符 |
| 底部导航 | 固定位置、同等分配、图标配名称，选中项明确；不需要每项都铺一块重色底 |
| 底部弹层 | 标题清楚、内部可滚动、底部安全区完整、退出方式明显 |
| 头像入口 | 页头和个人页使用同一默认角色，用户头像优先；显示尺寸随场景变化 |
| 收藏与附属动作 | 操作与主体入口区分，避免点收藏同时误进详情 |
| 加载、失败、空状态 | 说明当前发生了什么以及下一步；失败后解除忙碌状态并允许重试 |
| 返回路径 | 返回后尽量保留分组、选择和已输入内容，减少重复操作 |
| 动效 | 服务于切换和反馈，避免持续抢注意力；首页当前不自动轮播 |
| 可点击性 | 图标的视觉尺寸与点击区域分开考虑；水果节点当前最小44px，其他控件不能据此假定已全部达到相同标准 |

## 7. 当前可参考的尺寸与色值

| 项目 | 当前值 / 范围 | 用法 |
| --- | --- | --- |
| 页面背景 | `#F5F5F7` | 全局浅灰底 |
| 卡片表面 | `#FFFFFF` | 常规内容卡 |

| 春 / 夏 / 秋 / 冬底 | `#F0F4EE` / `#FBF1EB` / `#F7F0E5` / `#EEF3F7` | 四时星图背景 |
| 页面左右边距 | 28–36rpx | 同页保持共同边界 |
| 常用模块间距 | 16–24rpx | 大小屏允许调整 |
| 页面主标题 | 42–48rpx，部分小屏36–42rpx | 明确第一阅读层级 |
| 模块标题 | 29–36rpx | 次级层级 |
| 正文 / 操作 | 24–28rpx为常见起点 | 长正文还需配合行高 |
| 元信息 | 常见20–24rpx | 小字不承载唯一关键操作信息 |

| 按钮 / 输入框圆角 | 常见12–18rpx | 低于大卡的视觉体量 |
| 全局卡片阴影 | `0 4rpx 20rpx rgba(0,0,0,.025)` | 轻微区分层次 |
| 页头默认头像 | 76rpx | 暖白细边、轻阴影 |
| 水果节点 | 常规128rpx，小屏96rpx，最小44px | 肖像与点击区域 |
| 英文果名宽度 | 164rpx | 给长名称留空间 |

## 8. 可以直接沿用的页面组合

| 页面类型 | 推荐组合 |
| --- | --- |
| 发现 / 活动主入口 | 简洁页头 → 搜索 → 一张主要图片卡横向切换 → 两个次级入口 → 固定底栏 |
| 分类 / 知识主入口 | 标题与说明 → 一级分段 → 分组内容图形或卡片 → 少量快捷入口 |
| 游戏 / 工具主入口 | 简洁页头 → 一个主要功能大图 → 两个次要功能卡 → 功能进入子页 |
| 文化目录 | 标题与简短介绍 → 统一分组列表 → 摘要与独立收藏 → 正文子页 |
| 地点列表 | 筛选或分组 → 有来源的照片与名称、位置、简短说明 → 详情 |
| 正文阅读 | 标题与来源 → 舒适正文行高 → 必要插图 → 关联动作 |
| 个人 / 设置 | 头像身份区 → 分组功能和设置 → 说明与状态；允许垂直滚动 |
| 表单 | 先解释目的 → 按意义分组字段 → 清楚的选择态 → 明确主操作 → 就近反馈 |

## 9. 后续验收清单

- 第一眼能找到主要内容和主要动作。
- 同屏重点数量受控；新增内容有合适层级和去向。
- 图片构图适配容器，小屏裁切不伤主体。
- 图片与文字各有职责，标题不会落在最杂乱的区域。
- 标题、正文、说明和元信息可以明显区分。
- 同级元素对齐，组内与组间间距有规律。
- 底色、卡片、强调色有明确分工；辅助文字保持可读。
- 卡片、按钮、头像、图标来自同一套视觉语言。
- 所有选中态、计数和页面内容同步更新。
- 点击区域足够，收藏、编辑等附属动作不误触主入口。
- 四个主 Tab 在可用视口内完整呈现；长内容在合适的子页或内部区域滚动。
- 中英文、长标题、空数据、加载、失败、选中、禁用状态都检查。
- 小屏与大屏分别查看实际画面；检查文字越界、图文遮挡和底栏安全区。
- 回到上一页时，必要的选择与进度仍然保留。
- 图片压缩后仍清楚，离线所需资源完整，包体符合项目预算。
- 对于图谱等特殊布局，同时进行实际截图检查和坐标 / 碰撞检查。

当前星图曾完成两种模拟器尺寸、四季、两组、中英文共32种布局检查。该记录用于说明验收方法，不能替代未来改版后的重新检查。

## 10. 不宜机械照搬的部分

- 不把所有页面都锁成一屏：阅读、目录、表单和设置需要滚动。
- 不为了减少滚动把字号和点击区域不断缩小。
- 不要求每张图片都是同一种画风：应统一品牌气质，并服从封面、节点、头像各自职责。
- 不把图片面积当作唯一指标：完整主体、清楚文字和合适的信息量更重要。
- 不把四时星图的47%圆心、节点半径直接套给任意关系图：这些值与节点数、标签和画布尺寸有关。
- 不把大圆角、阴影、渐变堆在所有元素上：装饰应有用途和层级。
- 不把所有文字都处理成浅灰：轻盈不能牺牲阅读。
- 不把当前代码中残留的旧样式、字符图标混用或局部例外都当作设计目标。后续继续统一时，应沿用提炼后的规则。

## 11. 可复制的设计指令

> 延续果物四时记这轮视觉方向：使用系统无衬线字体、浅灰页面、白色与暖白表面、深绿操作色，以优质果物图片和清楚的信息层级为重点。先确定每页的主要任务，四个主Tab采用固定一屏的弹性框架，列表、正文、表单和复杂交互进入可滚动子页。图片先根据容器比例、主体位置与文字安全区域设计，图片内不生成界面文字。使用一张主要视觉与少量次级入口，统一对齐、间距、圆角和轻量阴影。封面负责叙事，水果节点负责识别，头像负责亲切感，导航图标保持简洁。保留已有功能入口和返回状态，检查大小屏、中英文、长文案与各种交互状态，以实际渲染结果确认清晰、完整、可用。

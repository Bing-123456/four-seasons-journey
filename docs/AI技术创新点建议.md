# AI 技术创新点建议（对着评分表找亮点）

## 0. 先说结论：现在这个亮点为什么"怪"

「果灵检测到只问国外就回一句固定话术」不适合当技术亮点，三个原因：

1. **它落在"内容口径"，不落在"AI 能力"上。** 官方评分里 AI 技术应用 20 分，要的证据是「结构化需求解析、资料检索与问答、**提取审核流程**、**失效处理**、**对照测试**」。一句边界话术一条都不占。
2. **它是规则，不是模型。** 一行 `if` 就能实现，而且我们已经用本地确定性闸门实现了——评委一眼能看穿"这不是 AI 算法"。把它包装成 AI 亮点，反而会在答辩时被追问"这跟 AI 有什么关系"。
3. **它和已有功能重复。** 果灵搜索本来就是"检索本地素材库再整理回答"，加个边界不产生新能力。队友自己也在群里说"确实会有一些重复"。

**处理办法**：这个功能留着（它确实是好产品细节），但把它降级成**内容合规层的一个组件**，别让它扛创新分。真正的亮点应该从下面这条主线里出。

## 1. 官方评分表（来自规划文档 3.3）

| 评分项目 | 分值 | 官方要的证据 |
|---|---:|---|
| 创新性 | 25 | 带来源的文化关系如何参与个性化行程；与固定路线、普通生成式行程的对照 |
| 需求分析 | 15 | 文献与公开资料研究、用户任务、真实原型试用、已证与未证需求区分 |
| **AI 技术应用** | **20** | **结构化需求解析、资料检索与问答、提取审核流程、失效处理和对照测试** |
| 项目实施 | 15 | 可操作主流程、模块接口、进度、协作记录、启动复现 |
| 应用成效 | 15 | 路线可行性、事实依据、完成任务用时等实测数据；保留失败案例 |
| 总结与展望 | 10 | 数据覆盖、公开资料时效、供给模拟等局限；真实试点条件与后续计划 |

关键：**20 分那栏列的五项，我们已经全做了，只是没被打包成一条技术主线。**

## 2. 零成本方案：把已有能力讲成「证据约束生成」

现在的 `/api/ask` 不是"让大模型讲文化"，而是**让大模型不可能编造文化**：

| 评分要求的证据 | 项目里已有的实现 |
|---|---|
| 结构化需求解析 | `/api/profile`：自然语言 → 结构化行程条件，每个字段必须附 `evidenceSpan` 原文片段 |
| 资料检索与问答 | `evidence.js`：BM25 词法检索 + 人工 subject/intent 门控 → 模型**只从候选里挑证据 ID** |
| 提取审核流程 | `validation.js` 结构校验 + `answerFromEvidence` 只允许核验原文拼接 + 来源 ID 全量比对 |
| 失效处理 | `withFallback` + `fallbackReason`：模型超时/输出不合法/不可用时，退回已审核摘要并**明确标注不是 AI 回答** |
| 对照测试 | `tests/` 286 项（含模型失败降级、迟到响应隔离、拒答用例）+ `scripts/evaluate-retrieval.js` |

**这条线的技术说法**：不是 RAG 的常规做法（"把资料塞进 prompt 让模型组织语言"），而是**抽取式、引用绑定、模型无写事实权限**的架构。模型输出被约束成"选 ID"这一个动作，事实性文字 100% 来自人工核验原文。

**能讲出来的量化指标**：幻觉率（结构上为 0，不是 prompt 求出来的）、引用可核对率 100%、拒答准确率、模型调用次数与 P95 时延。

这条线的好处：**不用新写代码就能拿到 20 分里的四项**，只需要补一个评测脚本、出一张对照表。

## 3. 要"加一个真算法"，按性价比排三个选项

### 3.1 领域重排模型微调（CrossEncoder）★ 首推

- **落点**：检索召回后做重排，直接改善问答取证质量。规划文档 8.1 已经定好路线。
- **为什么是硬亮点**：这是唯一能写出"我们自建领域数据、实际训练、独立评测"的成果，创新性 25 分和 AI 技术 20 分都能吃。评委对"自主训练"的认可度远高于"调 API"。
- **可量化**：Recall@k、MRR、nDCG；**基线（BM25 词法）vs 微调模型**的对照——这正是评分表要的"对照测试"。
- **成本**：需要标注 300–500 条"问题 + 候选资料片段 + 相关性"；小模型 CPU 可训。
- **诚实边界**：训练完成前只能写"拟训练/研究计划"，完成后写"基于开源基座的领域微调重排器"，不写"自训大模型"。

### 3.2 生成-审校闭环（Generator-Critic）

- **落点**：AI 民俗故事、文旅方案、文化讲解——凡是模型要自由写字的地方。
- **技术**：生成 → **事实校验器**（把生成文本回查证据库，逐句标记有无出处）→ 未通过则重写，再不过则降级为模板并标注"本机模板版"。
- **可量化**：审校拦截率、事实一致率、人工复核通过率、降级率。
- **成本低**，而且正好是队友提的"生成完之后再调一次 LLM review"——把它做成流水线，而不是再问一次模型。
- **加分点**：文化内容最怕编造，这套"生成必过审"的闭环就是产品说服力本身。

### 3.3 节气–果品–民俗知识图谱 + 多跳问答

- **落点**：**四时页**——正是队友觉得"只有文化、没有 AI"的地方。
- **技术**：从现有素材抽取实体与关系（节气 ↔ 果品 ↔ 民俗 ↔ 农具 ↔ 产地）→ 建图 → 多跳查询 + 路径解释。
- **能回答现有检索答不了的问题**：如"霜降为什么要吃柿子，跟哪个节气农事有关"需要跨三跳；现在是词法检索，跨不了。
- **可量化**：单跳/多跳问题的准确率、路径可解释率、与词法基线的对照。
- **成本中**，但四时页的观感提升最直接：从"静态文化框架"变成"可提问的知识网络"。

## 4. 备选（成本更低，分数略低）

| 选项 | 技术说法 | 指标 |
|---|---|---|
| 个性化文化学习路径 | 轻量知识追踪（答题正确率建模）+ 内容推荐 | 答题正确率提升、学习完成率、推荐命中率 |
| 识果 Top-k 评测 | 检索增强的细粒度品种识别（视觉 → 文化条目） | Top-1/Top-5 准确率、拒识率 |
| 端侧成本工程 | 本地规则优先、模型按需调用、分包异步化 | 模型调用次数下降、P95 时延、单次成本、降级率 |

## 5. 四时页到底放什么 AI（回答队友的诉求）

队友说"四时页面只有文化，没有 AI 算法的亮点"。**不建议**往那里塞一个"拒答国外水果"的规则，**建议**放这两样：

1. **知识图谱多跳问答**（3.3）——把静态文化框架变成可提问的网络，这是真算法。
2. **可溯源回答**（第 2 节）——每条回答都能点回原始出处，把"可信"做成看得见的东西。

一句话叙事：**四时是静态的完整文化框架，果灵是在这个框架上做检索、推理与取证的那层 AI。**

## 6. 建议对外的一句话

> 我们做的不是让模型讲文化，而是让模型的每一句文化表述都能回查到出处。

这句话同时覆盖创新性（带来源的文化关系）、AI 技术应用（检索/审核/失效/对照）和总结展望（局限与可信边界）。

## 7. 已经有现成的对照数据（比想象中好）

`npm run eval:retrieval` 现在就能跑，`evaluation/culture-seed.json` 是标注集（32 条：10 条 dev + 22 条冻结 evaluation），冻结集上**两组基线的实测对照**：

| 方案 | hit@1 | hit@3 | MRR | 资料不足召回 | 误拒率 |
|---|---:|---:|---:|---:|---:|
| BM25 词法 top3 | 0.714 | **1.000** | 0.845 | **0.000** | 0.000 |
| BM25 + 人工 subject/intent 门控（线上实际用的） | **0.857** | 0.857 | **0.857** | **1.000** | 0.071 |

（22 条冻结样本，14 条可答 / 8 条资料不足；报告里如实标注 `modelTraining: false, externalModelCalls: 0`）

这张表本身就是一个**能上台讲的发现**：意图门控把"该拒答的都拒住"从 0 提到 1.0，代价是 hit@3 从 1.0 掉到 0.857、误拒 7.1%。**这个取舍是实测出来的，不是拍脑袋说的**——评分表要的"对照测试"这项证据已经拿到了。

而且它顺手指出了下一个技术点该往哪打：**hit@3 的损失正好是重排模型要补的缺口**。基线已经量好了，微调只要比它高就有意义。

## 8. 下一步（按性价比排序）

1. **把这张表变成答辩材料**（半天，零风险）：扩标注集到 100+ 条（现在 32 条偏少，评委可能质疑样本量），补一组"加模型挑证据"的三档对照，产出 Recall@k / MRR / 拒答准确率的完整表。这一步同时补上评分表要求的"对照测试"。
2. **做生成-审校闭环**（1–2 天）：接在民俗故事/文旅方案上，产出拦截率与事实一致率数据。
3. **启动重排模型标注与微调**（1–2 周）：缺口已经量化（hit@3 −0.143），这是分值最高、也最需要提前启动的一项。

## P16「果灵搜索」接口实测

用户要求测试 P16 的搜索接口，看不同输入分别得到什么。产出一份 `docs/P16果灵搜索-接口实测报告-2026-09-27.md`，跑 74 个查询覆盖 11 组场景。

### 测试方法（可复用）

写了一个 stub 测试台 `tmp/p16-search-harness.js`：**不重写逻辑**，而是
1. `global.Page = def => captured = def` 截获页面定义
2. stub `wx`（getStorageSync / setStorageSync / setNavigationBarTitle / showToast / switchTab）与 `getCurrentPages`
3. `require` 页面文件 → 拿到 `def` → 造实例（`setData` 直接 Object.assign）
4. 调 `onLoad()` 初始化 `data.L`，然后直接调 `finishSearch(question)`

这套方法适用于任何小程序页面：**绕过 UI，直接驱动页面方法，测真实代码路径**。比重新实现一遍逻辑可信得多。

原始结果落 `tmp/p16-search-results.json`。

### 关键架构发现

**P16 完全不调用 `/api/ask`**，是纯本地检索。`search.js` 里 `/api/ask`、`answerQuestion`、`evidence` 出现次数均为 0，`service` 只出现 1 次（用于 EN 按钮的按需翻译）。

→ 协作文档「待确认清单 Q6」的描述**是错的**，需要更正。（Q6 原文：「P16 检索走本地文化库，/api/ask 仅在开启云端时增强证据排序」）

素材库：四季 48 条目 / 42 个不重名水果 / 每条 6 个固定分类（folk/history/craft/story/tools/health）/ 农谚 5 条 / 节气札 24 条。

### 发现的 8 个缺陷

**P0（答错级别，3 类）**
1. **子串匹配撞车** —— `matchFruits` 用 `question.indexOf(name) !== -1`，无词边界、无最长优先。42 个水果名里 **7 个会撞车**：杨梅（青梅+杨梅）、冬枣（枣+冬枣×2）、椰枣（枣+椰枣）、甘蔗×3、葡萄×2、柚子×2、脐橙×2
2. **凤梨 → 秋梨** —— 秋梨注册了别名「梨」，于是搜「凤梨」返回**梨**的内容。而菠萝条目正文里写着「菠萝也称凤梨」。同理：西梅/腊梅 → 青梅
3. **边界判定被绕过** —— `fruit-scope.js` 的注释专门写了防误判（"先摘掉境外果名，避免番石榴/葡萄柚里的石榴/葡萄被误判"），`classify()` 也确实正确返回 `scope='out'`；**但 `finishSearch` 先跑 `matchFruits`，命中就直接出答案，`classify` 根本没机会执行**。结果：番石榴→石榴、葡萄柚→葡萄、西梅→青梅、日本的柿子→河南柿子（答非所问且违反边界策略）

**P1（输出异常，3 类）**
4. **跨季同名水果重复 + 荒谬文案** —— `compare = fruits.length >= 2` 用的是**条目数**不是**不同水果数**。搜「甘蔗」输出「**甘蔗 与 甘蔗 与 甘蔗**的关键差别见上方各段；**两者**…都不同。」三段正文也重复
5. **`mixed` 分支跳过婉拒** —— 「河南能种蓝莓吗」→ 返回「没找到相关水果」，而单搜「蓝莓」能正确婉拒。加个国内地名反而降级
6. **农谚匹配取 `question.slice(0,4)`** —— 「谷雨前后种瓜点豆」命中，「**为什么**谷雨前后种瓜点豆」→ 取前 4 字「为什么谷」→ **0 命中**

**P2（2 类）**
7. **英文输入 0 命中** —— `matchFruits` 只匹配中文 `fruit.name`，但界面支持英文（i18n 有 `fruit_<id>` 词典层）。搜 loquat/watermelon/plum/persimmon 全部落空
8. **测试恰好绕过所有 bug** —— `tests/fruit-scope.test.js` 的「Guoling search page refuses foreign fruit」用例只测榴莲/枇杷/不存在的问法。**榴莲恰好不含任何收录水果名**，所以测试绿。换成番石榴就会红——典型的「测试选到了不触发缺陷的样本」

### 三个根因

1. `indexOf` 子串匹配没有优先级概念（「梅」既是青梅别名又是杨梅子串）
2. `finishSearch` 的分支顺序与 `fruit-scope` 的设计意图**相反**——防护代码写了，执行不到
3. 对比判定用条目数而非不同水果数

### 修复建议（已写进报告）

修 1（最长匹配优先 + 别名整词生效，可复用 `fruit-scope.js` 里 `explicitSubjects()` 现成的区间遮蔽写法）+ 修 2（把 `classify` 提到 `matchFruits` 之前，**只有 3 行改动**）+ 修 3（对比判定改用不同水果数）≈ **30 行代码解决 3 个 P0**。

另有修 4–8：跨季去重策略、农谚改关键词匹配、`mixed` 分支补边界提示、英文反查表、补 8 条回归用例。

**未动代码**——用户只要求测试，修复方案留在报告里等确认。

## 辅助果农场景：可训模型清单

用户问「辅助果农的场景有没有什么模型是可以训的」。产出一份 `docs/辅助果农-可训模型清单-2026-09-27.md`。

### 读代码后的关键发现

**1. 规则引擎已经「像个模型」了。** `seller-core.js` 的 `assess()` 返回 `model: 'inventory-balance-v1'`，输出 `status`（insufficient/clear/attention/urgent）+ `remainingKg` + `basis`（依据说明）+ `scenario`（哪些是假设）。**「规则基线 vs 训练模型」的对照框架天然存在，只缺被对照的模型。**

**2. 数据模型已按「可训练」设计。** `seller-store.js` 的状态有六张表：`batches`(≤100) / `events`(≤5000) / `riskSnapshots`(≤200) / `alerts`(≤200) / `plans`(≤100) / `feedback`(≤300)。两个关键钩子：
- 顶层 `excludeFromTraining: true` —— 演示/合成数据自动排除，不用人工筛
- `feedback` 表把 `planId` 和 `intentCount`(参与意向人数) + `actualCost` 连起来 → **效果建模的监督信号**
- `alerts` 表有 `read`/`handled`/`review` → **干预决策的弱标签**

**3. 但现在可用于训练的样本数 = 0。** 演示数据只有 1 批次 / 7 条事件 / 4 天；snapshots/alerts/plans/feedback 全空。

**4. 现有 `dailyKg` 估计是弱基线**：`assess()` 只有两条路——近 7 天已核对日均值，或卖家手填的 `assumedDailyKg`。这就是模型该补的缺口。

**5. 训练目标的原型已存在**：`ledger().daily` 是日净销量序列；`closedDates` 是卖家显式核对过的日子，可作监督信号权重。

### 六个可训模型（按「现在能不能开工」分三档）

**现在就能训（能自己造数据）**
- **A 果实成熟度/商品等级分级** —— 唯一能短期出真成果的。细粒度视觉分类 + **序数回归**（等级有序，相邻错误惩罚应小于跨级），主指标 **QWK 二次加权 kappa**，对照 Qwen-VL zero-shot + 人工分级。数据自己拍+标注 200–400 张，2–3 天
- **B 台账异常检测** —— 无监督零标注，稳健统计(MAD/IQR) + Isolation Forest。评测可用**程序化注入异常**构造，不需要真实数据。1 天

**卡数据，但架构已就绪（现在该埋点）**
- **C 日净销量预测** —— 特征：lag1–7、星期几、距截止天数、天气(Open-Meteo 免费)、物候、批次属性、visitor-flow。方法：梯度提升 + **分位数回归做区间**，主指标 **区间覆盖率**（比 MAE 更能说明价值）。**硬门槛：多批次×多天连续序列，现在差两个数量级。不要硬上**
- **D 提醒该不该发（干预决策/uplift）** —— 我认为被低估的方向。`alerts.read/handled/review` 就是弱标签，学「果农会不会处理」。指标：处理率 AUC、**无效提醒率下降**。**唯一「用得越久越准」且不依赖外部数据的方向**
- **E 方案→参与意向人数** —— 规划 8.3 阶段 B 的落地。**基线特别清晰：`createPlan()` 里硬编码的 `perVisitorAssumption: 8`**。且 `plans` 表同时存规则方案和 AI 草案，**天然对照实验**

**不该做**
- **F 滞销概率预测** —— 规划 7.7 已论证，那个判断是对的（批发价≠某地滞销、年鉴产量≠当前待售量）。守住，硬做会扣分

### 推荐主线

把闭环讲成「**训练数据生产机**」：填报 → 台账 → 规则测算 → 提醒 → 方案 → 执行反馈 → 回到台账，每步都产出 `(状态, 决策, 结果)` 三元组。

对外表述：**「我们不是训了个模型预测滞销，而是建了一条能持续生产训练数据的经营闭环，并用它把规则基线逐步替换为有实测增益的模型。」** 比硬说「已训成销量预测模型」诚实且有分量。

### 19 天建议
1. 训 A（成熟度分级）—— 唯一能短期出真成果
2. 训 B（异常检测）—— 1 天零标注
3. 给 C/D/E 做好埋点与数据导出，报告写「管线就绪 + 启动门槛」（门槛要在跑之前登记）

## ⭐ 重大结构澄清：AIC 有四类赛道，我们和那 30 位不在同一类

**触发**：用户指出 `notice-3/4776.html` 「没有提供模型训练的数据集和方向，只给了一个大而宽泛的方向」。

**产物**：`docs/AIC赛道结构澄清-为什么智能文化不给数据集-2026-09-27.md`

### 结论
**AIC 有四个赛道类别，规则完全不同：**

| 类别 | 交什么 | 数据集 | 排行榜 |
|---|---|---|---|
| **算法主题赛** ← 智能文化在这 | 技术报告 + 视频 + PPT | ❌ 无 | ❌ 无 |
| **算法挑战赛道** ← GitHub 那 30 位绝大多数在这 | 结果文件 + **代码 + 模型文件** | ✅ 有，分级开放 | ✅ 每小时刷新 |
| **算法应用赛道** | 现场对抗/实机 | 视赛题 | 赛马制 |
| **产业命题赛** | 视赛题 | 视赛题 | 视赛题 |

官方原文（两处一致）：**「本赛题为开放式赛题」「作品以技术报告形式呈现」**。
挑战赛道原文：**「获取初赛数据下载链接」「依托赛事方提供的训练数据集」「初赛排行榜每 1 小时刷新一次」「低于基线参考分数判定为无效成绩」「总决赛最终成绩 =（70% 排行榜得分 + 30% 答辩得分）」**。

### 一次解释清三件事
1. **为什么没有数据集** → 主题赛规则里就没有「数据」这一环，连赛题都不给，只给领域范围
2. **为什么 GitHub 挖到的 30 位全是挑战赛道的** → 挑战赛道总决赛**必须交代码和模型文件**并接受复现审核，**不开源过不了审**
3. **为什么智能文化 0 个开源仓库** → 主题赛代码**不是必交项**，只放百度网盘链接，**没有开源动机**。这是规则使然，不是参赛者藏着 → **「找不到往届作品」是结构性事实，到此为止，不用再找**

### ⚠️ 修正了我之前的一个错误判断
早先说「那 30 位的赛制、**评审偏好**、材料组织、答辩经验都跨赛道通用」——**「评审偏好」这半句是错的**。
一个教你怎么刷榜的人教不了你怎么写「应用成效」。**能照搬的只有三样**：总决赛线下答辩经验、材料组织规范、国赛技术深度基线。
**问法要改**：问「答辩怎么讲」「材料怎么组织」，不要问「怎么拿高分」。

### 战略含义（反直觉）
**「没有数据集」对我们是好事。** 竞争维度从「谁的分高」（拼算力）变成「谁的问题好、谁真落地了」（拼选题与真实数据）。我们的强项（完成度、真实用户、可运行 Demo）恰好是主题赛最吃的东西。

且 `附件1` 二（三）明确要求「**已在实际场景中应用并取得良好效果，展示清晰的应用案例和数据证明**」——直接对上「应用成效 15 分（数据详实）」。佐证材料清单里列了「**用户反馈、试点应用证明**」，这一栏别人填不满。

### 新识别的行动项
1. **启动软著申请**（小程序可申请，1-3 个月，佐证材料里唯一来得及自己办的硬凭证）
2. **整理《数据说明》**——`附件2` 附录 1 要求「原始数据、处理后的数据及数据来源说明」，我们的有源证据链（`catalog.js` 的 sources/facts + sourceIds）天生满足，别人没有
3. **停止检索「智能文化数据集」**——不存在
4. 「自训模型」问题依然存在且更棘手：主题赛不给数据集 → 训练数据必须自己造 → `辅助果农-可训模型清单` 里「成熟度分级 + 台账异常检测」可自造数据这条路依然成立

### 教训
**看到「不合常理」的现象，先怀疑自己搞错了分类，而不是怀疑对方漏了。** 用户一句「很奇怪诶」直接问出了整个赛道结构的误判。

## 五、古典模型训练方向：不微调 LLM，训三个小模型

**用户提问**：「微调 LLM 的话这个肯定是不够的呀；如果是训古典的一些模型，应该往哪个方向发展」

**产出**：`docs/古典模型训练方向与数据可行性-2026-09-27.md`（276 行，九节）

### 结论
**不要微调 LLM，去训「意图分类器 → 检索重排器 → 引用支持验证器」这三个古典模型。**
三者**共用同一条数据构造管线**（31 条事实 + 14 个来源出发），做一套数据训三个模型。

### 为什么不能微调 LLM（量化）
| 项 | LLM 微调需要 | 我们现有 | 差距 |
|---|---|---|---|
| 指令微调数据 | 1,000–10,000 条 (指令, 回答) | **0 条**（32 条是 (query, 事实ID)） | **15–300 倍** |

且「用 415 条让 LLM 生成几千条 QA 再微调」= **自生成自训自评**，评测失真，答辩一问就穿。
**唯一例外**：32 条标注（含 8 条拒答负样本）可做成「**文化领域幻觉评测集**」——这是**数据贡献**，比微调模型稀缺，且可公开。

### ⭐ 核心枢纽认知：内容库 ≠ 任务数据集
415 条不是「不够」，是「**形态不对**」。转换三种手法：
1. **问法扩增**：31 条事实 × 8–10 问法 = **250–310 条** (query, 正确事实)
2. **负样本自动构造**：换数字/地名/节气名 → 等量负样本，**零人工**
3. **干扰项采样**：每条 query 配 5–10 个非相关事实 → **3,000+ 对，免费**

⚠️ 用 LLM 生成**候选问法**+人工筛选是站得住的弱监督，**但报告必须写「问法由模型生成、人工筛选」，不能写「人工标注」**。

### ⭐⭐ 意外发现：`evidence.js` 里已有现成标签集
核查 `miniprogram/lib/evidence.js`（263 行）确认它是**手写规则**，脚本复核数量：
- **31 条 `annotations`** = 每条事实 → `(主语, [意图列表], 关键词串)` → **31 条已标注样本**
- **13 条 `subjects` 正则** = 主语标签体系**已定义**
- **22 条 `intents` 正则** = 意图标签体系**已定义**
- 文件自述：「An **explainable lexical baseline**, not an embedding model… constrained by **reviewed subject/intent annotations**」
- 输出 `retrievalMethod: 'lexical-bm25-intent-gates'`

→ **35 条正则可当弱标注器**，批量给无限问法打伪标签 → 数千条 (query, subject, intent) 训练集。
→ **顺序必须是「先分类器、后重排器」**：分类器数据现成（1 天），且它的输出正是重排器的输入特征。
→ **顺带解决隐患**：规则闸门在答辩时是弱点（「这算算法吗」）；换成学到的分类器/重排器后，规则降格为**特征和弱标注器**，性质完全不同。

### 有现成基线（可直接量化增益）
`test-results/retrieval-evaluation.json`：BM25+约束 → hit@1 **0.857** / hit@3 0.857 / MRR **0.857** / **拒答召回 1.000** / 误拒率 0.071。
→ 评审最爱「**有基线 + 有增益 + 有对照**」，我们三样都有。

### 不推荐的方向
- **日净销量预测 / 提醒该不该发 / 方案→参与人数**：数据模型就绪但**无真实数据**（events 仅 7 条/4 天，alerts/plans/feedback 全 0）→ 只做埋点 + **登记启动门槛**，**不编造准确率**
- **滞销概率预测**：需要可售库存/未来采收/订单/渠道成交/保鲜期/历史结果，**批发价 ≠ 某地滞销**，硬做扣分
- **LLM 微调**：见上

### 18 天计划（D1 弱标注 → D2 分类器 → D3-4 重排器 → D5-6 引用校验 → D7 异常检测 → D8-11 成熟度分级〔可砍〕→ D12-15 数据卡/模型卡）
**时间不够就砍 D8–D11**，保 D1–D7 三主线。

### 答辩话术要点
不讲「我们训了模型」，讲「**文化问答最怕答错和编造出处，我们分别训了重排器和引用支持验证器，hit@1 从 0.857 → X，F1 = Z，对比 5-gram 字面校验假阳性率下降 W**」。
四个强点：有基线有增益有对照 / 解决真问题 / **诚实交代边界（没数据就不训）** / 一次覆盖附录 1+2。

## 六、用户质疑「确实没啥模型可训」——核查后成立，方向转向视觉侧

**用户原话**：「哎 我突然觉得 这个里面 好像确实没啥模型 可以训练的」

**核查后结论：质疑基本成立。** 上一轮那三个文本方向（意图分类 / 检索重排 / 引用校验）的共同毛病是——**标签全部来自我们自己写的规则，没有独立监督信号**：
- 意图分类器 = 用 35 条正则打标签，再训模型模仿规则 = **知识蒸馏，教师是规则**；31 条标注分 13 类，**每类平均 2.4 条**
- 检索重排器 = 候选集**总共 31 条事实**，不是排序是「31 选 1」；hit@3 已 0.857，**天花板增益只有 0.143**
- 引用校验 = 负样本是「换个数字」，**字面比对就能查出来**，不是语义验证

**一句话**：这三个是「**把规则包装成模型**」，答辩撑不住。

### ⭐ 但漏了一个：唯一真正能训的模型在视觉侧
核查 `server/tasks.js` + `miniprogram/lib/playground-controller.js` 找到 **「果灵识果」**：

| 要素 | 事实 |
|---|---|
| 任务 | **14 类中国本土水果细粒度图像分类**（青梅/桑葚/樱桃/西瓜/桃子/李子/柿子/石榴/秋梨/苹果/枣/砂糖橘/瓯柑/冬枣） |
| 入口 | `playground` 页面「识果」按钮 → `wx.chooseMedia` 拍照 → `POST /api/identify-fruit`（**真实链路，活的**） |
| 当前实现 | qwen-vl zero-shot 从候选清单里选（`tasks.js:125-138`） |
| **负类（现成）** | `fruit-scope.js` 的 **`OUT_OF_SCOPE_FRUITS` 35 个域外果物**（榴莲/车厘子/蓝莓/牛油果/菠萝蜜…）→ 直接当 `unknown` 样本 |
| 监督信号 | **照片本身是客观的**，不是我们写的规则 → 独立信号 |
| 难对 | 砂糖橘 vs 瓯柑、枣 vs 冬枣、青梅 vs 李子、苹果 vs 秋梨 → **VLM 大概率栽在这** |

**收益不只是准确率，是工程收益**——`playground-controller.js:89-91` 注释自承：「qwen-vl 偶尔输出不合法 JSON、瞬时 5xx/超时」→ 所以加了**重试 2 次 + `model_*` 降级链**。换本地小模型可**整段删掉**，并额外得到：离线可用 / 零延迟 / 零成本 / 确定性输出 / **照片不出设备**。

**故事比「我训了个模型」好**：不是「加了个模型」，是「**把不稳定、要联网、要付费、会把用户照片传出去的云端调用，换成自训练本地模型——更准、更快、更省、更可靠、更保护隐私**」。

### ⚠️ 但第一步不是训模型，是测 VLM 基线
| VLM 14 类准确率 | 决策 |
|---|---|
| > 90% | ❌ **不训**，改写「VLM 细粒度识别评测报告」 |
| 70–90% | ⚠️ 做，但收益主要是**工程收益**，报告要诚实这么写 |
| < 70% | ✅ **值得训**，准确率 + 工程双重故事 |

测法：14 类 × 10 张 + 35 张域外 = **175 张**，跑 `/api/identify-fruit`，出**准确率 + unknown 拒识率 + 混淆矩阵**。**1 天，且即使不训也有价值。**

### ⚠️ 两个硬约束（别忘）
1. **主包硬上限 2 MiB**。量化后 MobileNetV3 约 4–10 MB → **必须走分包或云端推理**，先算清这笔账
2. **产品里没有成熟度分级入口**。`matureDate` 只是果农手填文本字段（`validation.js` 的 `optionalText`），无图片链路 → 成熟度分级从「✅ 现在就能」**降为 P3 / 可砍**

### 你真正要的「技术含量」不在训练，在架构
读完 `server/tasks.js`（174 行）后确认，这里的设计比训模型硬得多：
- **模型不许自由作答**：`// An unsupported factual question is never handed to an unconstrained LLM.` 证据不足直接返回，不交给模型；输出经校验（ID 必在候选集内、数量 1–4、`unanswerable` 必须是布尔），**任一条不满足就丢弃模型输出走本地兜底**
- **`// The model chooses evidence. Factual wording stays anchored to reviewed source records.`**
- **每个任务都有诚实降级且明确标注 mode**：`local-fallback` / `local-template` / `local-rules`，「服务挂了就说挂了，不编」
- **境外内容代码兜底**：`if (task === 'fruitStory' && local.outOfScope) return local;` —— 不靠 prompt 自觉
- 已有 32 条标注 + 5 个指标 + 2 组对照 = **完整的实验设计**

**对「智能文化」开放式赛题（无数据集、100% 专家评审），这套「可控生成 + 可解释 + 诚实降级 + 有评测」比「我们训了个模型」更对路。**

## 重大缺陷修复：WXML 里的 indexOf

客户反馈的「点击后没有内容」「爱心不变红」不是样式问题，是 `calendar.wxml` 把 `expandedCats.indexOf(item.cat) >= 0` 写在视图表达式里——**WXML 不执行数组方法，该调用恒为假**，所以 `wx:if` 永不成立、正文从来没渲染过，爱心类名也永远是空。

修法：`calendar.js` 新增 `decorateFruit()`，把 `open` / `fav` / `label` / `favId` 在 JS 里算好，wxml 只读 `item.open`、`item.fav`。同类隐患 `favorites.wxml` 的 `item.name.slice(0,1)` 一并改成 `item.initial`。`scripts/check-project.js` 已加规则拦截 WXML 里的方法调用。

## 果灵内容边界（境外问题回固定话术）

需求：只问国外 → 回「xx为外来引进我国的果品，不属于《四时》板块收录的中国本土原生水果。」；涉及国内外 → 照常回答。

- **关键认知：果灵有两条链路，模型都不写答案。** ①「四时」底部搜索框（`pages/search/search.js`）纯本地匹配素材库，不调模型；②文化详情页问果灵 → `/api/ask` → `evidence.retrieve` 检索，模型**只挑证据 ID**，答案文字由 `catalog.facts[].text` 拼。所以改 system prompt 改不了它说什么，必须做本地确定性闸门。
- 新增 `miniprogram/data/fruit-scope.js`（唯一边界来源，`classify()` → in/mixed/out）。接入 `search.js` 空态、`evidence.resolve()` **第一步**（放后面会被「资料不足」分支抢先）、`server/tasks.js` 的 ask prompt + fruitStory。
- **坑**：闸门必须放在 `resolve()` 最前面。一开始放在中段，`'榴莲怎么种？'` 被更早的 `if (!subject || !intent)` 拦成通用话术。
- **口径冲突（待用户拍板）**：《四时》内圈 13 种里，西瓜/石榴/苹果 都是境外传入，严格按"本土原生"会自我矛盾（西瓜还是中牟主案例）。现口径 = 「《四时》已收录（47 种）一律照常回答」，只拒收录之外的境外对象。话术里的"中国本土原生"建议改成"中国本土当季"。
- 顺手把 `matchFruits` 从只认内圈 13 种扩到链图全部 47 个节点。**遗留**：识果 `/api/identify-fruit` 候选清单还是 13 种，建议同步扩到 47。
- `npm test` 286 项全绿（新增 `tests/fruit-scope.test.js`）。

## 技术创新点梳理（用户觉得"果灵边界"当亮点很怪）

- 官方评分（规划文档 3.3）：创新性 25 / 需求分析 15 / **AI 技术应用 20** / 项目实施 15 / 应用成效 15 / 总结展望 10。AI 技术应用那栏要的证据 = 结构化需求解析、资料检索与问答、提取审核流程、失效处理、对照测试。
- **结论：这五项项目里全做了**，只是没打包成一条技术主线。建议对外统一讲「证据约束生成」：模型只能选证据 ID，事实性文字 100% 来自人工核验原文，幻觉率结构上为 0。
- 「果灵拒答国外水果」降级为内容合规层的组件，不扛创新分（是规则不是模型，且与搜索功能重复）。
- **`npm run eval:retrieval` 已有实测对照**（22 条冻结样本）：BM25 hit@1 0.714 / hit@3 1.000 / 拒答召回 0.000 → 加意图门控 hit@1 0.857 / hit@3 0.857 / 拒答召回 1.000 / 误拒 0.071。这个取舍是实测出来的，可直接当答辩材料；**hit@3 掉的那 0.143 正好是重排模型要补的缺口**。
- 标注集只有 32 条（10 dev + 22 eval），偏少，需要扩到 100+。规划文档 8.1 的领域重排模型（CrossEncoder 微调）是分值最高、最该提前启动的一项。
- 建议文档：`docs/AI技术创新点建议.md`。

## 追问：拦截国外水果是不是"让能力变少"

- **实测结论：能力增减 = 0。** 加规则前后 `evidence.retrieve('榴莲怎么种')` 候选都是 0 条——素材库根本没有榴莲/车厘子/蓝莓记录。变的只是措辞（"资料不足"→"不属于本板块"）。所以它不是砍功能，但也**不是能力增量**，当亮点讲会被问穿。
- 真正的成本：①口径和产品打架（山竹/释迦/草莓在四时页外圈有完整内容，果灵却说不收录）；②封死扩展；③演示死胡同。
- 已做的两处调整：`fruit-scope.js` 加 `const ENABLED = true`（一行关闭边界，对外可说"这是内容策略不是技术限制"）；加 `REDIRECTS` 把境外果品映射到就近收录水果，婉拒补一句"可以试试《四时》收录的荔枝、龙眼、黄皮"，固定话术一字不改。写测试时抓出 bug：巴西莓原本引导到"蓝莓"，而蓝莓自己也是境外果品——测试会校验每条引导都在收录范围内。
- **更大的发现**：`/api/ask` 证据库只有 31 条事实，全是中牟西瓜/瓜豆酱/裴李岗/河南博物院/大河村/猕猴桃/草莓/苹果这类**地点与手艺主题**，**和四时 47 种水果零重叠**。问枇杷/山竹/榴莲候选都是 0 条。真正答水果问题的是四时页底部搜索框，而它**不调模型**。要在四时页讲"可溯源问答"，得先把证据库扩到覆盖 47 种水果。

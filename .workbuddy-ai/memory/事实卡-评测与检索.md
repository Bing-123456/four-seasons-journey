## 一、消融实验台：`npm run eval:ablation`

`scripts/evaluate-ablation.js`。三组对照，同一模型同一 `temperature=0`：

| 组 | 定义 |
|---|---|
| A 裸 LLM | 不给资料，直接问 |
| D 朴素 RAG | 全部 31 条事实进上下文 + 明确提示「资料不足要如实说明」（**刻意选最强基线**） |
| C 本系统 | 本地闸门 + 模型选证（走 `server/tasks.js` 真实路径） |

**基线数字（`culture-seed-2026-09-28-v2`，22 条 = 14 可答 + 8 不可答）**：

| 组 | 拒答召回 | 编造率 | 误拒率 | 忠实度 | hit@1 | 模型调用 | 延迟 |
|---|---|---|---|---|---|---|---|
| A 裸 LLM | 0.625 | **0.250** | 0 | 0.286 | — | 22 | 1120ms |
| D 朴素 RAG | 1.000 | 0 | 0 | 0.714 | 0.917 | 22 | 1076ms |
| **C 本系统** | **1.000** | **0** | **0** | **0.929** | **0.929** | **14** | **631ms** |

**三条可写进技术报告的论点**：
1. 闸门把编造率 25% → 0；
2. 分层检索把忠实度 0.714 → 0.929（朴素 RAG 有 3 条「资料在手却说没有」）；
3. 本地闸门省 36% 模型调用、降 41% 延迟。

**设计纪律（改这个脚本时必须守住）**：
- **C 组的「是否拒答」用系统自身的 `unanswerable` 决策，不交给裁判**——那正是要被度量的东西。
  忠实度才三组统一送裁判，保证可比。
- 裁判与纯字面规则的拒答判定一致率会写进结果（`judgeRuleAgreement`）。
  **A/D 组一致率只有 0.50–0.625，说明裁判本身有噪声** → 数字只用于**组间对照**，不作绝对评价。
- 裁判是同一个模型，存在自我偏好；22 条样本量小，单条翻转带来 0.125 跳变。
  **这两条必须写进任何对外报告。**

**已知短板**：q024「郑州第六批非遗名录有多少项」——闸门给了含「61 项」的候选，模型没取出来，裁判判 `irrelevant`。待修。

## 二、检索层：闸门即检索（关键架构事实）

**实测（32 条评测问题全部）**：经过 subject/intent 闸门后，**候选池恒为 1 条**
（0 条 11 个、1 条 21 个，平均 1.00，最大 1）。

含义：**闸门用 `subject` + `intent` 两个离散标签直接定位到唯一事实，排序层在闸门之后完全冗余。**
所以 BM25 / 稠密 / RRF 在闸门之后跑出来完全一样。已固化成测试 `tests/retrieval-fusion.test.js`。

## 三、检索层 2×3 因子实验：`npm run eval:retrieval -- --dense`

因子：排序器（词法/稠密/混合）× 是否用人工审校标注。
**目的**：回答「hit@1 0.929 有多少来自算法、多少来自人工标注」。

| 组 | hit@1 | MRR | 拒答召回 |
|---|---|---|---|
| 纯 BM25（无标注） | 0.714 | 0.845 | 0.000 |
| **纯稠密（无标注）** | **0.929** | **0.964** | 0.000 |
| BM25+稠密 等权 RRF（无标注） | **0.786** ↓ | 0.893 | 0.000 |
| 带闸门的三组 | 0.929 | 0.929 | 1.000 |

- **语义模型可替代人工标注做召回**（零标注稠密 0.929 = 带标注 BM25）。
- **等权 RRF 是负收益**：融合前必须先度量各排序器单独质量，质量不对等时等权融合会被弱排序器拖累。
- **拒答能力完全来自闸门**，排序器不提供任何拒答能力（无标注三组拒答召回必然为 0）。
- **索引文本绝不掺入 annotations 的审校关键词**——掺进去等于把人工标注搬进向量层，对照实验立刻失效。

**调参纪律**：权重只在 **dev** 拆分上试；dev 只有 7 条可答问题（单条翻转 = 0.143），
**不足以支撑任何权重选择，因此采用未调参的等权结果**。
evaluation 拆分冻结用于报告，不据测试结果调优门限。

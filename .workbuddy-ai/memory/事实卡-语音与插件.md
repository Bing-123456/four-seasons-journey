# 事实卡 · 语音输入与微信插件

> `MEMORY.md` 的配套细节文件。只在这里放「查起来很贵、忘掉会再踩」的事实。
> 主要来源：2026-09-28 在微信开发者工具里的实测（`scripts/probe-plugin-wiring.js` 可复跑）。

## 一、双引擎结构（2026-09-28 起）

只服务**「问果灵」搜索页的语音输入**。**朗读是另一条链路**，走服务端 `/api/speech`
（DashScope TTS，7 种方言，`server/speech.js`）——两者共用同一个 DashScope key，但独立配置。

```
① 插件（首选）  requirePlugin('WechatSI') → getRecordRecognitionManager()
                流式；免费 250 条/分、3 万条/天；不消耗我们的额度
② 服务端（兜底）wx.getRecorderManager() 录音（mp3 / 16 kHz / 24 kbps / 60s）
                → readFile(base64) → POST /api/asr → server/asr.js → qwen3-asr-flash
```

`voice.engine` 暴露实际走的哪条（`'plugin' | 'server' | null`）——**降级必须可观测**。

**为什么两条都要**：插件体验好但**是否授权是后台状态，代码保证不了**（0.7.7 因此静默降级过一次）；
服务端零后台依赖、带方言参数，但没有流式中间结果、要消耗额度、需先配对。

## 二、⚠️ 插件回调必须用「赋值式」注册（最容易写错的一处）

实测得到的属性描述符与 `start` 源码：

```
onStart / onStop / onError / onRecognize
  → 都是 **可写数据属性（writable: true）**，出厂值都是空函数 `function(e){}`
manager.start 源码
  → function(s){ … setCallback("onStop", this.onStop),
                     setCallback("onError", this.onError),
                     setCallback("onRecognize", this.onRecognize),
                     setCallback("onStart", this.onStart), innerStreamRecoManager.start(s) }
```

`start()` 是**读属性当前值**再注册的，所以：

```js
manager.onStop = fn      // ✅ 对（官方示例代码的写法）
manager.onStop(fn)       // ❌ 错：静默空转，回调永远不来，界面表现为「点了没反应」
```

官方文档的**方法表**写成「onStop callback」，很容易被误读成注册器；**以官方示例代码为准**。

**对照——两条链路注册方式不一样，别互相套用**：

| | 注册方式 | 单例问题 |
|---|---|---|
| 插件 `recordRecoManager` | **赋值式** | 赋值即替换，天然幂等，不需要去重 |
| `wx.getRecorderManager()` | **注册器式** `recorder.onStop(cb)` | **会叠加监听器** → 必须 `WeakMap` 只绑一次 |

**为什么差点漏掉**：本机模拟器不支持录音，探测时两种写法都是「零回调」，
只有把 `start` 的源码 dump 出来才看清真相。

## 三、插件 API 事实

| 项 | 值 |
|---|---|
| provider | `wx069ba97219f66d99`（服务商：深圳市腾讯计算机系统有限公司） |
| `app.json` 声明 | `"plugins": { "WechatSI": { "version": "0.3.5", "provider": "wx069ba97219f66d99" } }` |
| 基础库要求 | ≥ `1.9.94`（插件内调用 `wx.getRecorderManager`） |
| `start({lang, duration})` | `duration` 默认 **60000**、**最大 60000**（不是 30s——30s 只是官方示例传的值）；`lang ∈ zh_CN / en_US / zh_HK / sichuanhua`，**无粤语档** |
| `onStop` 回调 | `{ tempFilePath, duration, fileSize, result }` |
| `onError` 回调 | **`{ retcode, msg }`** —— 是 **`retcode`**，不是 `code` |
| 错误码 | 负数 `-30001 ~ -40001`，共 14 个（`-30011` = 识别中又调 start；`-40001` = 频率限制） |
| `onRecognize` | **不在官方 API 文档里**，但实测存在，同样走赋值式 |

**配额**（官方文档）：语音输入 250 条/分钟、3 万条/天；文本翻译 500 次/分、10 万次/天；
语音合成 100 次/分、2 万次/天。需要更多要发邮件到 `wetranslate@tencent.com` 申请。

## 四、服务端兜底链路事实（`server/asr.js`）

| 项 | 值 |
|---|---|
| 模型 | `qwen3-asr-flash` |
| 端点 | `POST {DASHSCOPE_BASE_URL}/api/v1/services/aigc/multimodal-generation/generation`（**与 TTS 完全相同**） |
| 请求 | `{ model, input:{ messages:[{role:'user',content:[{audio:'data:audio/mpeg;base64,...'}]}] }, parameters:{ asr_options:{ language, enable_itn:true } } }` |
| 响应 | `output.choices[0].message.content[0].text` |
| ⚠️ 坑 | `asr_options` **必须在 `parameters` 里面**——写成顶层不报错但不生效 |
| ⚠️ 坑 | 小程序端用 `wx.request` 发 **base64 JSON**（不是 multipart）；`/api/asr` 的 body 上限刻意设 **3 MB**，**不走全局 `maxBodyBytes`（默认 16 KB）**——16 kHz/24 kbps 的 mp3 约 3 KB/s，base64 后约 4 KB/s，**全局上限只够约 4 秒**（3 秒≈12 KB 能过，5 秒≈20 KB 必 413） |
| 语言 | `zh`（含川/闽南/吴方言）/ `yue` / `en`；默认 `zh` |
| 体积 | 解码后音频 ≤ **1.5 MB**（16 kHz / 24 kbps ≈ 3 KB/s，够 8 分钟） |
| 实测延迟 | **374–499 ms**（3 秒音频，真模型） |

**错误分级**——`asr_empty` 与 `asr_unavailable` 必须分开，否则「模型没听清」会被当成「服务故障」计入监控：

| code | HTTP | 含义 |
|---|---|---|
| `asr_invalid` | 400 | 格式/语言/音频字节不合法 |
| `body_too_large` | 413 | 解码后音频 > 1.5 MB |
| `asr_empty` | 422 | provider 正常应答，但一个字都没听出来 |
| `asr_unavailable` | 502 | provider 调用失败 |
| `asr_disabled` | 503 | 未配置 key，提示改用键盘 |

**其他纪律**：
- 音频容器签名只判「**是不是音频**」，不判「与声明格式是否一致」——iOS/Android 录出的头部有差异，
  按声明格式严格比对会误杀真录音。宁可放过（交给 provider 判），也不误拒用户。
- **录音不落盘**：收到 base64 直接送模型，只回文字。
- 闭环验证法（不新增任何音频素材）：**用 `/api/speech` 合成一句已知文本 → 下载音频 → 喂给 `/api/asr` → 比对文字**。
  已进 `scripts/smoke-service.js` 的 `speech-then-asr-round-trip`；本机一次性版在 `tmp/verify-asr-e2e.js`。

⚠️ **微信开发者工具不支持录音，必须在真机验证。** 本机验证只覆盖「除真实麦克风以外」的全部逻辑。
真机上要确认：① 插件**流式**回填是否正常；② 摘掉插件声明后能否**顺畅降级**；
③ iOS 录出的 mp3 能否被服务端 `looksLikeAudio` 认下——**这是唯一没被本机验证覆盖的一段**。
